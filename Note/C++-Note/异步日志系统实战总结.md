| SyncLogger | 日志级别、格式化、流式接口、线程安全写入 | MemorySink 断言 |

## 关键知识梳理

### 1. 同步日志简单但容易阻塞业务线程

同步日志把格式化、加锁和 IO 都放在调用路径中，适合低频日志和调试场景，但高并发下会放大锁竞争和 IO 等待。

### 2. 异步日志用后台线程吸收 IO

异步 logger 的核心是缩短业务线程临界区：前台只追加缓冲，后台批量写 sink。正确关闭时必须等待缓冲写完，否则容易丢最后一批日志。

### 3. Sink 抽象决定扩展性

Logger 不应直接依赖文件或控制台。通过 Sink 接口，后续可以扩展网络 sink、压缩 sink、滚动 sink 或测试 sink。

### 4. 性能指标需要严谨 benchmark

当前 demo 是 smoke test，不是最终性能结论。吞吐、延迟和第三方对比都需要固定场景和稳定统计。

## 构建验证

```powershell
cmake -S CPP-Practice/async_logger -B CPP-Practice/async_logger/build
cmake --build CPP-Practice/async_logger/build --config Release
.\CPP-Practice\async_logger\build\Release\async_logger_demo.exe
```

验证结果：全部 `[PASS]`，当前 enqueue smoke test 约 2.548 μs/message。

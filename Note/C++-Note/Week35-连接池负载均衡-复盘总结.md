# Week35 连接池与负载均衡复盘总结

## 核心目标

Week35 实现连接池和负载均衡策略，为后续 RPC 客户端打基础。

## 连接池

连接池的目标是复用已建立连接，减少 TCP 握手和资源初始化成本。典型接口包括：

- acquire：获取连接。
- release：归还连接。
- mark_unhealthy：健康检查失败后跳过后端。

## 负载均衡

本周实现两种策略：

- RoundRobin：简单轮转，适合后端能力接近的场景。
- LeastConn：选择当前活跃连接最少的后端，适合请求耗时差异较大的场景。

## 复盘结论

连接池是 RPC 客户端性能的基础设施。它不只是缓存连接，还要和健康检查、超时、负载均衡、熔断策略协作。

# Week22 双缓冲异步日志复盘总结

## 核心目标

Week22 实现异步日志：业务线程写前台缓冲，后台线程批量 flush 到 sink。

## 数据流

1. 业务线程调用流式接口生成日志内容。
2. `AsyncLogger::log` 将格式化后的日志追加到前台缓冲。
3. 条件变量唤醒后台线程。
4. 后台线程交换缓冲，批量写入 sink。
5. `flush/stop` 等待已接收日志全部写完。

## 关键点

- 前台路径只做短临界区追加，降低业务线程等待 IO 的概率。
- 后台线程批量处理，减少 sink 写入频率。
- 析构时必须 stop 并 join，避免进程退出时丢日志。
- 正确性验证比性能结论更优先：先确保 accepted 和 written 一致。

## 当前结果

demo 验证 4 线程共 8000 条日志无丢失，`flush` 后 memory sink 数量与 accepted/written 一致。

## 复盘结论

异步日志的本质是把 IO 延迟从业务线程转移到后台线程，但这不自动等于性能胜利。吞吐和延迟必须用固定环境、固定 sink、足够规模的 benchmark 才能下结论。

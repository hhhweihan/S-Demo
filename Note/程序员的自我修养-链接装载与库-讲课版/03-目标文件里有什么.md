# 03-目标文件里有什么

## 这一章的核心问题

上一章说汇编器会生成目标文件，比如 `.o`。这一章就打开这个黑盒：目标文件里到底有什么？

大白话说，目标文件不是“一整块机器码”，它更像一个打包好的半成品，里面分门别类放着代码、数据、符号表、重定位信息、调试信息等。

## 目标文件为什么要分段

因为不同内容用途不同，权限也不同。

常见段有：

- `.text`：代码段，放机器指令。
- `.data`：已初始化的全局变量和静态变量。
- `.bss`：未初始化或初始化为 0 的全局变量和静态变量。
- `.rodata`：只读数据，比如字符串常量。
- `.symtab`：符号表。
- `.strtab`：字符串表。
- `.rel.text` / `.rela.text`：重定位表。

为什么要这么分？因为后面链接和装载都要靠这些分类来处理。代码段可以只读可执行，数据段可读写，BSS 段不需要在文件里存一堆 0。

## .text 段：真正的指令

`.text` 里放的是 CPU 要执行的机器指令。

比如你写：

```c
int add(int a, int b) {
    return a + b;
}
```

编译后，`add` 对应的机器指令就会放在 `.text` 段。

不过这里的地址不一定是最终运行时地址。因为单个 `.o` 文件还不知道最终会放到可执行文件的哪里。

## .data 段：有初始值的数据

比如：

```c
int global = 100;
```

这个变量有明确初始值 `100`，所以它要在目标文件里保存这个初始内容，通常放到 `.data`。

## .bss 段：默认是 0 的数据

比如：

```c
int counter;
static int cache[1024];
```

这些变量默认初始化为 0。目标文件没必要真的存 1024 个 0，只需要记录：程序运行时给我留这么大一块清零的空间。

这就是 `.bss` 的意义：节省文件体积。

## .rodata 段：只读数据

比如：

```c
printf("hello\n");
```

字符串常量 `hello\n` 通常放在 `.rodata`。它应该是只读的，如果程序试图修改字符串常量，可能会崩溃。

## ELF 文件头是什么

ELF 文件头就像目标文件的身份证和目录页。它告诉工具：

- 这是 ELF 文件。
- 是 32 位还是 64 位。
- 是小端还是大端。
- 目标 CPU 架构是什么。
- 段表在哪里。
- 程序入口在哪里。

工具如 `readelf -h` 看的就是这些信息。

## 段表是什么

段表记录每个 section 的信息，比如：

- 段名。
- 段类型。
- 文件偏移。
- 段大小。
- 对齐要求。
- 权限标记。

链接器要靠段表知道每段内容在哪里、应该怎么合并。

## 符号表是什么

符号表是链接器最关心的东西之一。

你可以把符号理解为“名字”。函数名、全局变量名、静态变量名，都可能出现在符号表里。

符号表里通常记录：

- 符号名。
- 符号类型：函数、对象、段等。
- 绑定属性：局部、全局、弱符号。
- 符号所在段。
- 符号的值或偏移。
- 符号大小。

链接器看到一个未定义符号，就会去其他目标文件或库里找同名定义。

## 字符串表为什么存在

符号名和段名都是字符串，如果每个表项里都直接塞字符串，会很浪费，也不好管理。

所以 ELF 通常把字符串集中放进字符串表。其他表项只记录一个偏移，意思是：去字符串表的某个位置开始读名字。

## 重定位表是什么

目标文件里有些地址现在还不能确定。

例如：

```c
extern int global;
int get() { return global; }
```

编译当前文件时，`global` 到底在哪个地址还不知道。于是汇编器留下一个重定位项，告诉链接器：这里将来要修正，修正时用 `global` 这个符号的地址。

重定位表记录：

- 哪个位置需要修。
- 依赖哪个符号。
- 用哪种修正方式。
- 是否有附加值。

## C++ 名字修饰为什么重要

C 语言函数名比较直接，`foo` 通常就是 `foo`。

C++ 支持函数重载：

```cpp
void foo(int);
void foo(double);
```

如果链接器只看 `foo`，就分不清两个函数。所以 C++ 编译器会把函数名、参数类型等编码进符号名，这叫名字修饰。

这也是为什么 C++ 调 C 库时经常要写：

```cpp
extern "C" {
    void c_func();
}
```

意思是：这个函数按 C 的符号规则处理，不要用 C++ 名字修饰。

## 强符号和弱符号

简单理解：

- 强符号：更硬的定义，比如普通函数、初始化过的全局变量。
- 弱符号：可被覆盖的定义。

链接器遇到同名符号时，会按规则选择。常见规则是强符号优先，强符号重复通常报错，弱符号可以被强符号覆盖。

## 本章最重要的 takeaway

目标文件是链接器能看懂的半成品。它不仅有代码和数据，还有符号表和重定位表。理解目标文件，才能理解链接器为什么能把很多模块拼起来。

## 建议动手实验

```bash
gcc -c simple.c -o simple.o
readelf -h simple.o
readelf -S simple.o
readelf -s simple.o
objdump -r simple.o
```

观察：

- 哪些变量进入 `.data`。
- 哪些变量进入 `.bss`。
- 函数名在符号表里是什么样。
- 哪些地方产生了重定位项。

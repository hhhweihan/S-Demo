# 13-运行库实现

## 这一章的核心问题

前面讲了很多运行库的作用，这一章更进一步：如果我们自己实现一个很小的运行库，需要做哪些东西？

这就是 Mini CRT 的意义。

它不是为了替代真正的 glibc 或 MSVC CRT，而是为了让你亲手把入口函数、堆、I/O、字符串、格式化输出、C++ 构造析构这些知识串起来。

## Mini CRT 要实现什么

一个最小运行库至少要有：

- 程序入口函数。
- 调用 `main` 的逻辑。
- 退出流程。
- 堆初始化。
- `malloc/free`。
- 基本文件 I/O。
- 字符串函数。
- 简单 `printf`。
- C++ 的 `new/delete`。
- 全局构造析构。
- `atexit`。

看起来很多，但每个都可以先做最小版本。

## 入口函数怎么写

如果不用系统默认运行库，你就得提供自己的入口。

入口函数大概做：

1. 从操作系统给的初始环境中拿到参数。
2. 初始化堆。
3. 初始化 I/O。
4. 调用全局构造函数。
5. 调用 `main`。
6. 调用退出函数和全局析构。
7. 把返回值交给操作系统。

这能让你真正理解：`main` 是被别人调用的。

## 堆怎么实现

最简单的堆分配器可以这样做：

- 向操作系统申请一大块内存。
- 每个内存块前面放一个头部，记录大小和是否空闲。
- `malloc` 时遍历空闲链表，找一块够大的。
- 如果太大，就切一块给用户，剩下继续空闲。
- `free` 时把块标记为空闲，必要时和相邻空闲块合并。

这不是最高效的算法，但足够理解堆管理的基本思想。

## 为什么内存块要有头部

用户拿到的是一段可用内存：

```text
[user data]
```

但分配器自己还得知道这块多大、是不是空闲、前后块是谁。所以真实布局可能是：

```text
[block header][user data]
```

当用户调用 `free(p)`，分配器会从 `p` 往前找到 block header，再把这块放回空闲链表。

这也解释了为什么越界写很危险：你可能把分配器自己的元数据破坏掉。

## 文件 I/O 怎么实现

Mini CRT 里可以把文件抽象成一个结构体，里面保存：

- 文件句柄或文件描述符。
- 当前状态。
- 缓冲区。
- 是否到达 EOF。
- 是否出错。

Linux 下底层可能调用 `read/write/open/close`。

Windows 下底层可能调用 `ReadFile/WriteFile/CreateFile/CloseHandle`。

上层提供类似 `fread/fwrite/fopen/fclose` 的接口。

## 字符串函数为什么适合自己写

`strlen`、`strcmp`、`strcpy` 看起来很简单，很适合理解运行库基础。

比如 `strlen` 就是从字符串起点开始数，直到遇到 `\0`。

但也正因为简单，容易忽视安全问题：

- 源字符串没有 `\0` 会越界读。
- `strcpy` 目标缓冲区不够会溢出。
- `strcmp` 要注意字符比较和结束条件。

## printf 难在哪里

`printf` 的核心是格式化字符串。

比如：

```c
printf("x=%d, s=%s\n", x, s);
```

它要做：

1. 扫描格式字符串。
2. 普通字符直接输出。
3. 遇到 `%` 解析格式。
4. 从可变参数里取对应类型。
5. 把数字、字符串、字符转换成文本。
6. 写到输出流。

Mini CRT 可以先只支持 `%d`、`%s`、`%c`、`%x`，不要一上来追求完整标准。

## new 和 delete 怎么实现

C++ 的 `new` 可以简化理解为：

```text
operator new 分配内存 -> 调用构造函数
```

`delete` 是：

```text
调用析构函数 -> operator delete 释放内存
```

`operator new` 底层通常可以调用 `malloc`，`operator delete` 可以调用 `free`。

所以 Mini CRT++ 只要实现这些操作符，就能支持基本动态对象。

## 全局构造和析构怎么实现

编译器会把全局对象构造函数的地址放到某些表里。

运行库入口在调用 `main` 前，遍历构造函数表并调用。

析构函数可以注册到 `atexit`，程序退出时再按顺序调用。

这块最能体现编译器、链接器、运行库三者配合。

## atexit 怎么实现

`atexit` 本质上是维护一个函数指针数组或链表。

用户调用：

```c
atexit(cleanup);
```

运行库把 `cleanup` 存起来。

程序退出时，运行库按规则把这些函数依次调用。

真实实现还要考虑线程安全、动态库卸载、调用顺序等，Mini CRT 可以先做简单版。

## stream 和 string

C++ 的 iostream 和 string 是更高层的运行库能力。

Mini CRT++ 可以做一个非常简化的版本，让你理解：

- `cout` 最终还是要写文件或控制台。
- `string` 本质上要管理动态内存、长度、容量和拷贝。

标准库真实实现非常复杂，但最小版本能帮你建立直觉。

## Mini CRT 的价值

它最大的价值不是产出一个好用库，而是让你把前面章节串起来：

- 链接器要找到你的入口。
- 装载器把程序放进内存。
- 入口函数准备运行环境。
- 堆分配器管理动态内存。
- I/O 调用系统服务。
- C++ 对象生命周期由运行库调度。

你自己写一遍，就会知道平时那些“理所当然”的函数其实都有人在背后干活。

## 本章最重要的 takeaway

运行库不是魔法。它是建立在操作系统接口、链接器约定和编译器生成信息之上的一层基础设施。Mini CRT 把这些机制缩小到你能看懂、能动手实现的规模。

## 建议动手实验

- 用 `-nostdlib` 链接一个自定义入口函数。
- 实现一个固定大小内存池版本的 `malloc/free`。
- 实现只支持 `%d/%s` 的 `printf`。
- 实现 `operator new/delete`。
- 写一个全局对象，验证构造和析构是否被调用。

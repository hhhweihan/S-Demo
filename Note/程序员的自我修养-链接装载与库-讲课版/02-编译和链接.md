# 02-编译和链接

## 这一章的核心问题

这一章回答一个最常见但最容易被忽略的问题：你敲下 `gcc main.c -o main` 以后，到底发生了什么？

很多人把这个过程都叫“编译”，但严格说，它至少包含四步：

```text
预处理 -> 编译 -> 汇编 -> 链接
```

这四步的产物不同，出错方式也不同。理解它们以后，很多编译错误、链接错误就不再玄学。

## 第一步：预处理

预处理主要处理这些东西：

- `#include`：把头文件内容展开进来。
- `#define`：替换宏。
- `#if/#ifdef/#endif`：根据条件决定保留哪些代码。
- 删除注释。

比如：

```c
#include <stdio.h>
#define N 10
```

预处理后，`stdio.h` 里的声明会被塞进你的源文件，`N` 会被替换成 `10`。

注意：头文件不是链接进来的，是在预处理阶段被文本展开的。

## 第二步：编译

编译阶段把预处理后的 C/C++ 代码变成汇编代码。

编译器内部大概做这些事：

- 词法分析：把字符流切成 token，比如关键字、标识符、数字。
- 语法分析：判断 token 能不能组成合法语法树。
- 语义分析：检查类型、声明、作用域这些语义问题。
- 中间表示：把源码变成一种便于优化的中间形式。
- 优化：删除无用代码、简化表达式、内联、循环优化等。
- 生成目标汇编：输出具体 CPU 架构的汇编代码。

如果你写错语法，比如少了分号，通常在这里报错。

## 第三步：汇编

汇编器把汇编代码变成目标文件，也就是 `.o` 或 `.obj`。

目标文件里已经有机器指令了，但它还不是最终可执行文件。因为它里面可能还有很多“暂时不知道”的东西。

例如 `main.o` 里调用了 `printf`，但 `printf` 的实现不在 `main.o` 里。汇编器只能先记录：这里需要一个叫 `printf` 的符号，后面链接器你来处理。

## 第四步：链接

链接器负责把多个目标文件、静态库、运行库启动代码拼起来。

它主要解决两个问题：

### 1. 符号解析

假设 `main.o` 里调用了 `foo()`，`foo.o` 里定义了 `foo()`。链接器要把这个调用关系对上。

如果找不到定义，就会出现类似：

```text
undefined reference to `foo`
```

或者 Windows 下：

```text
unresolved external symbol foo
```

### 2. 地址重定位

每个目标文件单独编译时，并不知道自己最终会被放到可执行文件的哪个地址。所以里面的跳转地址、全局变量地址很多都是临时的。

链接器把所有模块排好位置以后，要把这些临时地址修正成最终地址。这个过程叫重定位。

## 为什么链接器需要单独存在

因为 C/C++ 支持“分开编译”。你可以把一个项目拆成很多 `.c/.cpp` 文件，每个文件单独编译成 `.o`，最后再链接。

好处是：

- 一个文件改了，不用重新编译全部文件。
- 不同模块可以独立开发。
- 库可以提前编译好，别人只链接使用。

坏处是：

- 跨文件的名字要靠链接器解决。
- 声明和定义不一致时，问题可能拖到链接阶段才暴露。

## 声明和定义要分清

声明是告诉编译器：“有这么个东西”。

```c
int add(int, int);
```

定义是实际把这个东西做出来：

```c
int add(int a, int b) {
    return a + b;
}
```

只有声明没有定义，编译可能过，链接会失败。

## 本章最常见的坑

### 坑 1：头文件里写了函数定义

如果普通函数定义放在头文件里，然后被多个 `.c/.cpp` include，可能导致重复定义。除非它是 `inline`、模板，或者有特殊处理。

### 坑 2：只加了头文件，没链接库

很多第三方库要两步：

- include 头文件，让编译器知道函数声明。
- 链接 `.lib/.a/.so/.dll` 对应的库，让链接器找到实现。

只 include 不链接，编译可能过，链接会失败。

### 坑 3：把链接错误当编译错误

编译错误通常是语法、类型、声明问题。链接错误通常是符号找不到、重复定义、库顺序不对。

## 本章最重要的 takeaway

编译解决“单个源文件怎么变成机器代码”，链接解决“多个模块怎么拼成一个整体”。以后看到错误时，先判断它发生在哪个阶段，解决方向就清楚很多。

## 建议动手实验

```bash
gcc -E hello.c -o hello.i
gcc -S hello.i -o hello.s
gcc -c hello.s -o hello.o
gcc hello.o -o hello
```

然后分别打开这些文件看：

- `.i`：预处理后的巨大文本。
- `.s`：汇编代码。
- `.o`：目标文件，不能直接当文本看。
- 可执行文件：链接后的最终产物。

# 04-静态链接

## 这一章的核心问题

前面我们已经有了很多 `.o` 文件。现在问题来了：这些 `.o` 怎么变成一个真正能运行的程序？

答案就是静态链接。

静态链接的大白话解释：把多个目标文件和需要的库代码拼成一个完整可执行文件，并且把所有函数、变量的引用都对上地址。

## 链接器主要做两件事

### 第一件事：空间与地址分配

每个 `.o` 文件都有自己的 `.text`、`.data`、`.bss` 等段。

链接器会把同类段合并：

```text
main.o 的 .text
foo.o 的 .text
bar.o 的 .text
        ↓
可执行文件里的 .text
```

然后给它们安排最终地址。

### 第二件事：符号解析与重定位

符号解析解决“名字对应谁”。

重定位解决“地址填多少”。

比如 `main.o` 里调用 `foo`，链接器要先找到 `foo` 在 `foo.o` 里的定义，然后算出 `foo` 最终地址，再把调用指令里的占位地址修正掉。

## 为什么要合并相似段

合并相似段有几个好处：

- 代码集中放，方便设置只读可执行权限。
- 数据集中放，方便设置可读写权限。
- 减少文件结构复杂度。
- 便于装载器按页映射。

从链接视角看是 section 合并；从运行视角看，最后还会变成适合装载的 segment。

## 重定位到底在修什么

举个例子：

```c
extern int global;
int read_global() {
    return global + 1;
}
```

编译 `read_global` 所在文件时，编译器不知道 `global` 最终地址。于是目标文件里会留下一个洞，并在重定位表里记录：这个位置将来要用 `global` 的地址修。

链接器最后知道 `global` 放在哪里，就把这个洞补上。

所以重定位不是抽象概念，它就是在修机器指令或数据里的地址字段。

## 符号解析怎么工作

链接器会收集所有输入文件的符号：

- 有的符号是定义，比如 `foo` 函数在 `foo.o` 里定义。
- 有的符号是引用，比如 `main.o` 里调用了 `foo`。
- 有的符号是局部的，只在当前目标文件内部用。
- 有的符号是全局的，可以被其他文件引用。

链接器要保证每个外部引用都能找到一个合适定义。

如果找不到，就是未定义符号。

如果找到多个强定义，就是重复定义。

## COMMON 块是什么

老 C 语言里经常有这种写法：

```c
int global;
```

如果多个文件里都这么写，链接器怎么处理？历史上有一种 COMMON 块机制，把这类未初始化全局变量先当成“公共块”，最后由链接器统一分配。

现代编译器默认行为可能变化，比如 GCC 现在常用 `-fno-common`，重复定义会更早暴露。

你只要记住：COMMON 是 C 语言历史包袱之一，和未初始化全局变量的链接处理有关。

## C++ 为什么让链接更复杂

C++ 有很多特性会让链接器更忙：

- 函数重载导致名字修饰。
- 模板可能在多个目标文件里生成相同实例。
- 内联函数可能重复出现。
- 虚函数表需要生成和合并。
- 全局对象需要构造和析构。
- 异常处理需要额外表结构。

所以 C++ 的 ABI 很重要。ABI 规定了这些东西在二进制层面怎么表示。

## 静态库怎么链接

静态库本质上是一包 `.o` 文件，Linux 下常见 `.a`，Windows 下常见 `.lib`。

链接器处理静态库时，通常不是把整个库全部塞进可执行文件，而是只拿需要的成员。

例如你的程序只用到了库里的 `foo.o`，那链接器可能只抽取这个成员，不会把库里其他无关目标文件都放进去。

## 为什么库顺序会影响链接

在 GNU ld 这类链接器里，链接通常从左到右扫描。

如果命令是：

```bash
gcc -lfoo main.o
```

链接器先看 `libfoo.a` 时，还不知道后面的 `main.o` 需要什么，可能不会抽取库成员。等看到 `main.o` 需要 `foo` 时，库已经扫过去了，于是报错。

正确方式通常是：

```bash
gcc main.o -lfoo
```

大白话：谁需要库，谁要放在库前面。

## 链接脚本是什么

链接脚本就是告诉链接器：输出文件要怎么排。

它可以控制：

- 入口点是谁。
- 每个段放到什么地址。
- 段的顺序。
- 哪些 section 合并到哪些输出段。

普通应用很少手写链接脚本，但写操作系统内核、裸机程序、嵌入式程序时经常需要。

## 本章最重要的 takeaway

静态链接不是简单复制粘贴，而是一个严肃的地址和符号整理过程。它把一堆半成品目标文件变成一个地址确定、引用闭合的可执行文件。

## 建议动手实验

```bash
gcc -c main.c -o main.o
gcc -c foo.c -o foo.o
nm main.o
nm foo.o
gcc main.o foo.o -o app
```

再试试静态库：

```bash
ar rcs libfoo.a foo.o
gcc main.o -L. -lfoo -o app
```

然后故意调换顺序，观察链接错误。

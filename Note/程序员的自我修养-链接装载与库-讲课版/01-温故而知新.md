# 01-温故而知新

## 这一章先讲什么

这一章像是正式上课前的“补基础”。作者不是为了单独讲操作系统，而是想先告诉你：一个程序能跑起来，背后不是只有 C/C++ 代码，还有 CPU、内存、操作系统、进程、线程、虚拟内存这些东西一起配合。

你可以把程序想成一个演员，源代码只是剧本。真正演出的时候，还需要舞台、灯光、导演、道具、工作人员。这里的舞台就是操作系统给进程准备的运行环境。

## 从 Hello World 说起

你写：

```c
#include <stdio.h>

int main() {
    printf("Hello World\n");
    return 0;
}
```

看起来只有几行，但它要真正输出一行字，需要经历很多层：

- 编译器把源码变成机器能看懂的指令。
- 链接器把你的代码和 C 运行库接起来。
- 操作系统创建进程，把可执行文件装进虚拟地址空间。
- 运行库先初始化，再调用 `main`。
- `printf` 处理缓冲区和格式化输出。
- 最后通过系统调用把内容交给操作系统，让终端显示出来。

所以 `Hello World` 不是简单例子，它是整本书的缩影。

## 操作系统到底帮你做了什么

大白话说，操作系统主要做三件事：

1. 管 CPU：谁先运行，谁后运行，每个程序用多久。
2. 管内存：每个程序能用哪些地址，不能碰哪些地址。
3. 管设备：磁盘、键盘、屏幕、网卡这些硬件不能让程序随便直接操作。

如果没有操作系统，程序就得自己处理硬件细节。那写一个普通应用会非常痛苦，而且多个程序之间也很容易互相踩内存、抢设备。

## 为什么需要虚拟内存

虚拟内存是这本书后面很多内容的基础。

你程序里看到的地址，比如 `0x400000`、`0x7ff...`，一般不是物理内存条上的真实位置，而是虚拟地址。操作系统和 CPU 的内存管理单元会把虚拟地址翻译成物理地址。

这样做有几个好处：

- 每个进程都觉得自己有一套独立地址空间。
- 一个进程乱写内存，不容易直接破坏另一个进程。
- 程序不需要关心自己被放在物理内存的哪个位置。
- 操作系统可以按需把页面调入内存，不用一次性加载全部内容。

一句话：虚拟内存给程序制造了一个“独立房间”的错觉。

## 分段和分页怎么理解

分段是按用途分：

- 代码段：放机器指令。
- 数据段：放已初始化的全局变量。
- BSS 段：放未初始化或初始化为 0 的全局变量。
- 堆：放动态申请的内存。
- 栈：放函数调用、局部变量、返回地址。

分页是按大小切：

操作系统把内存切成一页一页，比如常见 4KB。一页可以在物理内存里，也可以暂时不在。程序访问时如果页面不在，就触发缺页异常，操作系统再把它调进来。

分段更像“按房间用途分区”，分页更像“按砖块大小搬运”。

## 线程是什么

进程是资源容器，线程是执行流。

一个进程里可以有多个线程。它们共享这个进程的大部分资源，比如全局变量、堆、打开的文件。但每个线程有自己的栈和寄存器状态。

这就带来两个结果：

- 好处：线程之间共享数据方便，切换成本通常比进程低。
- 坏处：多个线程同时改同一份数据，很容易出问题。

比如两个线程同时执行 `count++`，它看起来是一句代码，但机器层面可能是读、加、写三个步骤。如果两个线程交错执行，最后结果可能少加一次。

## 线程安全怎么理解

线程安全就是：多个线程同时使用这段代码或这份数据，也不会产生错误结果。

常见办法：

- 加锁：同一时刻只让一个线程进入关键区域。
- 原子操作：让某些简单操作不可被打断。
- 线程局部存储：每个线程一份数据，互不干扰。
- 避免共享：能不共享就不共享，这是最干净的办法。

## 本章最重要的 takeaway

这一章的重点不是让你背操作系统概念，而是建立一个意识：程序不是直接跑在硬件上的，它跑在操作系统创建的进程环境中。后面讲链接、装载、动态库、运行库，本质上都离不开这个环境。

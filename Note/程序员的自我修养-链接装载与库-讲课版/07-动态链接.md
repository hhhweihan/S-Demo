# 07-动态链接

## 这一章的核心问题

静态链接会把需要的库代码放进可执行文件。那为什么还要动态链接？

因为很多库大家都要用。如果每个程序都把同一份库代码打包进去，磁盘浪费，内存也浪费。库升级也麻烦，每个程序都要重新链接或重新发布。

动态链接的思路是：程序运行时再把共享库装进来，多个程序可以共享同一份库代码。

## 动态链接解决了什么

主要解决三个问题：

1. 节省空间：库代码不用复制进每个可执行文件。
2. 方便升级：库修 bug 后，程序可能不用重新链接就能受益。
3. 支持插件：运行时按需加载模块。

但它也带来新问题：

- 启动时需要找库、装库、重定位。
- 版本不兼容会导致程序跑不起来。
- 符号冲突会出现奇怪行为。
- 调试时要多考虑动态链接器和共享库路径。

## 共享库为什么不能写死地址

假设 `libfoo.so` 固定要求装到 `0x10000000`。如果另一个库也想装到这个地址，就冲突了。

静态可执行文件地址比较容易确定，共享库不行，因为它会被很多不同程序加载，每个程序地址空间布局可能不同。

所以共享库最好能装到哪里都能运行。这就是地址无关代码 PIC 的意义。

## PIC 是什么

PIC 是 Position Independent Code，地址无关代码。

大白话：代码里尽量不要写死绝对地址，而是用相对寻址或间接表来找到真正地址。

这样共享库被加载到不同地址时，代码段不用大面积修改。代码页就可以被多个进程共享。

如果代码段需要被修改，每个进程都得有自己的私有副本，共享就打折了。

## GOT 是什么

GOT 是 Global Offset Table，全局偏移表。

你可以把 GOT 理解成共享库里的“地址通讯录”。

代码想访问某个外部变量或函数时，不直接把地址写死在指令里，而是去 GOT 表里查。动态链接器在装载时把真实地址填进 GOT。

这样代码本身不用改，只改数据表。

## PLT 是什么

PLT 是 Procedure Linkage Table，过程链接表。

它主要服务于函数调用，尤其是延迟绑定。

当程序第一次调用外部函数，比如 `printf`，流程大概是：

1. 先跳到 PLT 里的一个桩代码。
2. PLT 发现真实地址还没解析。
3. 进入动态链接器。
4. 动态链接器找到 `printf` 的真实地址。
5. 把地址写进 GOT/相关表项。
6. 以后再调用 `printf`，就直接跳真实地址，不再解析。

这就是延迟绑定：第一次用到时才解析。

## 为什么要延迟绑定

因为程序依赖很多函数，但一次运行未必都会用到。

如果启动时把所有外部函数都解析完，启动会变慢。延迟绑定把成本推迟到第一次调用时。

当然也可以关闭延迟绑定，让程序启动时一次解析完。这样启动慢一点，但运行中第一次调用不会突然多一次解析成本。

## .interp 段是什么

`.interp` 里记录动态链接器路径。

在 Linux 上，一个动态链接的程序不是直接由自己完成所有装载工作的。内核发现它需要动态链接器后，会先把动态链接器装起来，让动态链接器继续加载其他共享库、处理重定位。

## .dynamic 段是什么

`.dynamic` 像是动态链接的配置表。里面记录：

- 依赖哪些共享库。
- 动态符号表在哪里。
- 字符串表在哪里。
- 重定位表在哪里。
- GOT/PLT 相关信息在哪里。
- 初始化和终止函数在哪里。

动态链接器就靠这些信息干活。

## 动态符号表和普通符号表有什么区别

`.symtab` 是完整符号表，常用于链接和调试，发布时可能被 strip 掉。

`.dynsym` 是动态链接必须保留的符号表，记录运行时需要解析的导入导出符号。

所以动态链接程序即使被 strip，通常仍然需要保留 `.dynsym`。

## 动态链接器怎么工作

大致流程：

1. 自举：动态链接器先让自己能运行起来。
2. 读取主程序的 `.dynamic`。
3. 找到 `NEEDED` 依赖库。
4. 按搜索路径加载共享库。
5. 建立全局符号表范围。
6. 处理重定位。
7. 调用各模块初始化函数。
8. 跳转到程序入口。

最微妙的点是：动态链接器自己也是共享对象，但它要先在没有别人帮忙的情况下完成最基本的重定位，这叫自举。

## 全局符号介入是什么

动态链接里，同名全局符号可能被别的模块“截胡”。

比如主程序和某个共享库里都有同名函数，动态链接器搜索符号时可能优先找到主程序里的版本。这样共享库内部本来以为调用自己的函数，结果调用到了外面的同名函数。

这就是符号介入。它可以用于 hook，也可能导致坑。

## 显式运行时链接

除了程序启动时自动加载共享库，你也可以手动加载。

Linux 常用：

```c
void* handle = dlopen("libfoo.so", RTLD_NOW);
void* sym = dlsym(handle, "foo");
dlclose(handle);
```

这适合插件系统：程序启动时不知道有哪些插件，运行时扫描目录，发现一个库就加载一个。

## 本章最重要的 takeaway

动态链接的核心是：把库代码从可执行文件里拿出去，运行时再通过动态链接器、符号表、重定位、GOT/PLT 等机制接回来。

它带来共享和灵活，也带来版本、路径、符号冲突和启动开销问题。

## 建议动手实验

```bash
gcc -fPIC -shared foo.c -o libfoo.so
gcc main.c -L. -lfoo -o main
ldd ./main
readelf -d ./main
readelf -r ./main
objdump -d -j .plt ./main
```

重点看：

- `NEEDED` 依赖。
- `.dynamic` 信息。
- GOT/PLT 相关重定位。
- 第一次函数调用和后续函数调用的差别。

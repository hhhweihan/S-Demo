# 09-Windows 下的动态链接

## 这一章的核心问题

Linux 下动态库是 `.so`，Windows 下动态库是 DLL。

这一章讲 Windows 的动态链接机制：DLL 怎么创建，程序怎么使用 DLL，导入表和导出表怎么工作，为什么会有 DLL Hell。

## DLL 是什么

DLL 是 Dynamic Link Library，动态链接库。

它和 exe 一样是 PE 格式，只是用途不同：

- exe 通常是程序入口。
- dll 通常提供函数、类、资源，供 exe 或其他 dll 调用。

一个进程可以加载很多 DLL。Windows 系统 API 本身也大量通过 DLL 暴露。

## 使用 DLL 的两种方式

### 1. 隐式链接

编译链接时就告诉链接器：我要用某个 DLL 的函数。

通常你会有：

- 头文件：声明函数。
- 导入库 `.lib`：告诉链接器符号来自哪个 DLL。
- DLL 文件：运行时真正加载。

程序启动时，Windows 装载器会根据导入表自动加载依赖 DLL。

### 2. 显式运行时链接

程序运行时自己加载：

```c
HMODULE h = LoadLibrary("foo.dll");
FARPROC p = GetProcAddress(h, "foo");
FreeLibrary(h);
```

这适合插件、可选功能、延迟加载。

## .lib 不一定是静态库

Windows 下 `.lib` 有两种常见含义：

- 静态库：里面有真正代码。
- 导入库：里面没有完整实现，只告诉链接器这个函数来自某个 DLL。

这是很多初学者会混淆的地方。

如果你链接的是导入库，运行时仍然需要 DLL 在系统能找到的位置。

## 导出表是什么

DLL 想让别人调用自己的函数，就要导出符号。

导出方式常见有：

```c
__declspec(dllexport) int add(int a, int b);
```

或者用 DEF 文件控制导出。

导出表记录 DLL 对外提供哪些名字或序号。

## 导入表是什么

exe 或 dll 如果依赖其他 DLL，会在 PE 导入表里记录：

- 依赖哪个 DLL。
- 从这个 DLL 导入哪些函数。

装载时，Windows 装载器读取导入表，加载对应 DLL，然后把函数地址填好。

## IAT 是什么

IAT 是 Import Address Table，导入地址表。

程序调用导入函数时，通常不是直接跳到目标 DLL 的地址，而是通过 IAT 间接跳转。

装载器会把真实函数地址写进 IAT。这样程序代码里只需要通过表项调用。

这和 Linux 下 GOT/PLT 的思想有相似处。

## 基地址和重定位

DLL 有一个首选装载基址。如果加载时这个地址空着，就可以直接用。

如果这个地址已经被别的模块占了，DLL 就要换个地址加载。换地址以后，里面写死的绝对地址就要修正，这叫重定基或基址重定位。

重定位会增加装载成本，也可能影响页面共享。

## 按序号导出

DLL 函数可以按名字导出，也可以按序号导出。

按序号导出的好处是查找快、表更小。坏处是可读性差，而且一旦序号变了，兼容性会出大问题。

所以对外稳定 API 要非常谨慎使用序号。

## 导入函数绑定

导入函数绑定是一种优化：提前把导入函数地址算好写进去。这样装载时如果 DLL 没变，可以少做一些查找。

但如果 DLL 更新或地址变化，绑定信息就可能失效，装载器还要重新处理。

## C++ 和 DLL 为什么麻烦

C++ 跨 DLL 边界有很多坑：

- 函数名会被修饰，不同编译器规则不同。
- 类布局、虚表、异常机制依赖 ABI。
- STL 容器跨 DLL 传递很危险。
- 一个 DLL 分配内存，另一个 DLL 释放内存，可能因为 CRT 不同而出错。

工程上常见做法是：DLL 对外导出 C 风格接口，或者明确规定同一编译器、同一运行库、同一 ABI。

## DLL Hell 是什么

DLL Hell 指 DLL 版本混乱导致程序互相影响。

典型场景：

- 程序 A 需要旧版 `foo.dll`。
- 程序 B 安装时覆盖成新版 `foo.dll`。
- 新版不兼容旧版。
- 程序 A 突然坏了。

后来 Windows 引入了 side-by-side assembly、应用本地 DLL、清单等机制来缓解，但动态库版本问题仍然需要认真管理。

## 本章最重要的 takeaway

Windows 动态链接的核心也是“运行时把外部函数地址接起来”。只不过它通过 PE 导入表、导出表、IAT、装载器、DLL 搜索规则来完成。

理解 DLL 的关键不是会写 `__declspec(dllexport)`，而是知道链接期、装载期、运行期分别谁在做什么。

## 建议动手实验

```bat
cl /LD foo.c
cl main.c foo.lib
dumpbin /exports foo.dll
dumpbin /imports main.exe
```

再写一个显式加载版本：

```c
LoadLibrary("foo.dll");
GetProcAddress(handle, "add");
```

对比隐式链接和显式链接生成的导入表差异。

# 10-内存

## 这一章的核心问题

程序跑起来以后，内存到底怎么分布？函数调用为什么能一层层进去又一层层回来？`malloc` 和 `new` 分配的内存从哪里来？

这一章主要讲两个大块：栈和堆。

栈负责函数调用这条线，堆负责动态内存这条线。

## 进程内存布局先建立起来

一个普通进程的虚拟地址空间大致可以分成：

- 代码段：放机器指令。
- 只读数据段：放字符串常量等。
- 数据段：放已初始化全局变量。
- BSS 段：放未初始化或零初始化全局变量。
- 堆：动态分配内存。
- mmap 区：共享库、内存映射文件、大块内存等。
- 栈：函数调用和局部变量。
- 内核保留区域：用户态不能随便访问。

不同系统布局会不同，但大方向类似。

## 栈到底是什么

栈是一块按“后进先出”方式使用的内存。

函数调用特别适合用栈。比如：

```c
main -> foo -> bar
```

调用 `foo` 时，栈上压入 `foo` 的栈帧。`foo` 调 `bar` 时，又压入 `bar` 的栈帧。`bar` 返回时，先弹出 `bar` 的栈帧，再回到 `foo`。

这就像一摞盘子，最后放上去的先拿走。

## 栈帧里有什么

一个函数的栈帧可能包含：

- 返回地址：函数执行完回到哪里。
- 上一个栈帧的位置。
- 局部变量。
- 临时变量。
- 保存的寄存器。
- 传给下一个函数的参数。

具体长什么样取决于 CPU 架构、调用约定、优化级别。

## 为什么不能返回局部变量地址

比如：

```c
int* bad() {
    int x = 10;
    return &x;
}
```

`x` 在 `bad` 的栈帧里。`bad` 返回后，它的栈帧就失效了。你拿到的地址指向一块已经不属于你的临时区域，后面可能被别的函数调用覆盖。

所以这类 bug 有时不立刻崩，但非常危险。

## 调用惯例是什么

调用惯例规定函数调用时大家怎么配合。

它会约定：

- 参数放寄存器还是栈上。
- 参数从左往右压还是从右往左压。
- 返回值放哪里。
- 哪些寄存器由调用者保存。
- 哪些寄存器由被调用者保存。
- 栈由谁清理。

如果调用惯例不匹配，轻则参数读错，重则栈被破坏。

## cdecl 和 stdcall 大白话

在 32 位 x86 里经常见：

- cdecl：调用者清理栈，支持可变参数，比如 `printf`。
- stdcall：被调用者清理栈，Windows API 里常见。

为什么 cdecl 支持可变参数？因为只有调用者知道自己到底传了几个参数，所以让调用者清理更合理。

## 函数返回值怎么传

小整数、指针这类返回值，通常放寄存器里。

大结构体对象可能不能简单塞进寄存器，就可能由调用者提前准备一块空间，把地址偷偷传给被调用函数，让被调用函数把结果写进去。

所以“return 一个大对象”在底层可能比你想象中复杂。当然现代编译器有返回值优化，会尽量减少拷贝。

## 堆是什么

堆是给动态分配用的内存区域。

你调用：

```c
malloc(100);
new Object;
```

得到的内存通常来自堆或 mmap 区。

栈的生命周期由函数调用自动管理，堆的生命周期由程序员或运行库管理。你申请了，就要在合适时候释放。

## malloc 不是每次都找内核

很多人以为 `malloc` 每次都系统调用一次。实际通常不是。

运行库会先向操作系统申请一大块内存，然后自己在用户态管理。小块分配就在这块大内存里切。

这样做是因为系统调用成本高，不能每次申请几十字节都进内核。

## Linux 堆管理

Linux 下传统方式是 `brk/sbrk` 扩展进程堆顶。

大块内存也可能用 `mmap` 单独映射。

现代 malloc 实现会很复杂，比如按大小分桶、线程缓存、快速链表、合并空闲块等。

## Windows 堆管理

Windows 提供 Heap API，比如：

- `HeapCreate`
- `HeapAlloc`
- `HeapFree`

CRT 的 `malloc/free` 可以建立在 Windows 堆之上。一个进程也可以有多个堆。

## 堆分配器要解决什么问题

堆分配器的工作不是“找一块空地”这么简单。它要考虑：

- 分配速度要快。
- 释放后能复用。
- 碎片不能太严重。
- 多线程下要安全。
- 小对象和大对象策略不同。
- 内存对齐要正确。

## 内部碎片和外部碎片

内部碎片：你要 10 字节，分配器给了 16 字节，多出来的 6 字节用不上。

外部碎片：总空闲内存很多，但分散成很多小块，凑不出一块连续的大内存。

堆分配算法很大一部分就是在和碎片做斗争。

## new/delete 和 malloc/free 的区别

`malloc/free` 只管内存，不管对象构造析构。

`new/delete` 管对象生命周期：

- `new`：先分配内存，再调用构造函数。
- `delete`：先调用析构函数，再释放内存。

所以不要混用：

```cpp
int* p = new int;
free(p); // 错
```

## 本章最重要的 takeaway

栈管理函数调用，堆管理动态内存。栈快但生命周期短，堆灵活但需要管理。很多崩溃、内存泄漏、野指针、栈破坏问题，本质都和这两块内存的规则有关。

## 建议动手实验

- 在调试器里看函数调用栈。
- 打印局部变量、全局变量、malloc 内存的地址，比较它们分布。
- 写一个返回局部变量地址的例子，观察警告和运行行为。
- 用 Valgrind、ASan 或 Windows 调试工具检查越界和泄漏。

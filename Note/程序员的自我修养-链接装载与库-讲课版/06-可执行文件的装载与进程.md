# 06-可执行文件的装载与进程

## 这一章的核心问题

前面讲链接器生成了可执行文件。现在问题变成：这个文件躺在磁盘上，操作系统怎么把它变成一个正在运行的进程？

这一章讲的就是“装载”。

大白话说，装载不是把整个 exe 一口气复制进内存，而是操作系统根据可执行文件里的装载信息，给进程建立虚拟地址空间映射，让程序看起来已经准备好了，真正访问时再按需把页面调进来。

## 进程虚拟地址空间是什么

每个进程都有自己的虚拟地址空间。你可以理解成操作系统给每个进程发了一张“虚拟地图”。

这张地图里通常有：

- 程序代码区域。
- 全局数据区域。
- 堆。
- 栈。
- 共享库映射区域。
- 内存映射文件区域。
- 内核保留区域。

不同进程可以看到相同的虚拟地址，比如都觉得自己的代码从某个地址开始，但背后的物理内存映射可以完全不同。

## 装载不是简单复制

老想法可能是：程序要运行，就把整个可执行文件读进内存。

现代操作系统通常不是这样做。

它会把可执行文件的某些部分映射到进程地址空间。真正执行到某一页，或者访问某一页数据时，如果那页还没在物理内存里，就触发缺页异常，操作系统再把这一页从磁盘读进来。

这叫按需分页。

好处很明显：

- 启动更快，不用一次加载全部内容。
- 没用到的代码和数据不用占物理内存。
- 多个进程运行同一个程序时，代码页可以共享。

## 覆盖装入是什么

覆盖装入是早期内存小的时候用的办法。

假设程序很大，但某些模块不会同时用到，就让它们共用同一块内存。需要 A 时把 A 装进去，需要 B 时再用 B 覆盖 A。

这需要程序员自己设计模块覆盖关系，很麻烦。现代虚拟内存和分页机制普及后，覆盖装入就不再是普通应用的主流方式。

## 页映射怎么理解

页映射可以理解成：

```text
虚拟地址页 -> 物理内存页 或 磁盘文件某一页
```

程序访问某个虚拟地址时，CPU 查页表。如果页表说这个页已经在物理内存里，就直接访问。如果不在，就触发缺页异常。

操作系统处理缺页异常时，会判断：

- 这个地址是不是合法？
- 如果合法，对应文件的哪一页？
- 需要什么权限？读、写、执行？
- 把它调入哪个物理页？

如果地址不合法，就可能变成段错误或访问违规。

## 从操作系统角度看进程创建

一个程序启动时，操作系统大概做这些事：

1. 创建进程控制结构。
2. 创建新的虚拟地址空间。
3. 读取可执行文件头，确认格式是否合法。
4. 根据装载表映射代码段、数据段等区域。
5. 如果是动态链接程序，找到动态链接器。
6. 初始化用户栈，放入参数和环境变量。
7. 设置 CPU 寄存器，让指令指针指向入口地址。
8. 把进程放入调度队列，等待运行。

注意这里的入口地址通常不是 `main`。

## ELF 的链接视图和执行视图

ELF 里有两个视角：

- Section：链接视图，给链接器看的。
- Segment：执行视图，给装载器看的。

`.text`、`.data`、`.rodata` 这些是 section。装载时，操作系统更关心 program header 里的 segment，比如：

- 一个只读可执行 segment，里面可能包含 `.text`。
- 一个可读写 segment，里面可能包含 `.data` 和 `.bss`。

为什么要分两套？因为链接器需要精细分类，装载器需要按权限和页映射高效加载。

## 堆和栈放在哪里

进程地址空间里，堆和栈通常分开。

- 堆：动态内存，`malloc/new` 常从这里分配。
- 栈：函数调用，局部变量，返回地址，参数等。

很多系统里，堆大致向高地址增长，栈大致向低地址增长。当然具体布局会受系统、架构、安全机制影响。

## 初始栈里有什么

程序刚启动时，操作系统会在栈上放一些信息：

- `argc`：参数个数。
- `argv`：参数字符串数组。
- 环境变量。
- 辅助向量：给运行库和动态链接器的一些系统信息。

运行库入口会从这些信息里整理出 `main(int argc, char** argv, char** envp)` 需要的参数。

## Linux 装载 ELF 的大致流程

简单说：

1. 内核读取 ELF Header。
2. 检查魔数、架构、类型等是否合法。
3. 读取 Program Header。
4. 映射 PT_LOAD 段到虚拟地址空间。
5. 如果有 `.interp`，说明需要动态链接器，于是先装载动态链接器。
6. 建立初始栈。
7. 跳到入口地址开始执行。

对于动态链接程序，真正先执行的可能是动态链接器的入口，而不是程序本体入口。

## Windows PE 的装载

Windows 装载 PE 也有类似任务：

- 映射 PE 节到进程地址空间。
- 处理导入表，加载依赖 DLL。
- 如果基址冲突，处理重定位。
- 设置权限。
- 调用 TLS 回调和入口点。

概念上和 ELF 类似，只是格式和具体机制不同。

## 本章最重要的 takeaway

可执行文件变成进程，不是“复制进去然后运行”这么简单。更准确地说，操作系统根据文件里的装载信息创建虚拟地址空间映射，准备栈和入口，然后让 CPU 从入口地址开始执行。

## 建议动手实验

Linux 下：

```bash
readelf -l a.out
cat /proc/$(pidof a.out)/maps
```

你要观察：

- program header 里的 LOAD 段。
- 进程 maps 里的可执行文件映射。
- 共享库映射。
- 栈 `[stack]`。
- 堆 `[heap]`。

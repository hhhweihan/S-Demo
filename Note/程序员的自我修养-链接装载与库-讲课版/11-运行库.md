# 11-运行库

## 这一章的核心问题

这一章要回答一个很关键的问题：程序真的从 `main` 开始吗？

答案是否定的。

`main` 是你写的入口，但在 `main` 之前，运行库已经做了很多事。`main` 返回之后，运行库还要继续收尾。

## 什么是运行库

运行库就是 C/C++ 程序运行时依赖的一套基础设施。

它提供：

- 程序入口启动代码。
- `malloc/free`。
- `printf/fread/fwrite` 等 I/O。
- 字符串函数。
- 环境变量处理。
- 全局构造析构。
- 线程相关支持。
- `atexit` 退出回调。

你平时以为这些“自然存在”，其实都是运行库提供的。

## main 之前发生什么

一个 C 程序启动时，通常先进入运行库入口，比如 `_start` 或 CRT startup。

入口代码大概做这些事：

1. 从初始栈取出 `argc/argv/envp`。
2. 初始化运行库内部状态。
3. 初始化堆。
4. 初始化标准输入输出。
5. 准备线程局部数据。
6. 调用 C++ 全局对象构造函数。
7. 调用你的 `main`。

所以 `main` 不是第一棒，它只是运行库准备好环境后交给你的那一棒。

## main 返回之后发生什么

`main` 返回不代表进程立刻什么都不管了。

运行库还要：

- 拿到 `main` 的返回值。
- 调用 `exit` 流程。
- 执行 `atexit` 注册的函数。
- 调用 C++ 全局对象析构函数。
- 刷新并关闭 I/O 缓冲。
- 把退出码交给操作系统。

所以程序退出也有一整套流程。

## C 标准库和运行库是什么关系

C 标准库定义了一组标准接口，比如：

- `printf`
- `malloc`
- `strlen`
- `fopen`
- `qsort`

运行库是这些接口在某个平台上的具体实现。

Linux 常见 glibc、musl。Windows/MSVC 有自己的 CRT。接口看起来差不多，但内部实现和边界行为可能不同。

## glibc 和 MSVC CRT

glibc 是 Linux 世界常见 C 运行库，功能很庞大。

MSVC CRT 是 Windows/MSVC 体系的运行库，和 Windows API、PE、PDB、线程模型结合紧密。

它们都提供 C/C++ 程序需要的基础设施，但入口函数、初始化表、I/O、线程局部存储等实现细节不同。

## 运行库和多线程

单线程时代，很多东西可以用全局变量。

多线程来了以后就麻烦了。比如 `errno`：

```c
errno = EINVAL;
```

如果 `errno` 是普通全局变量，多个线程同时调用库函数就会互相覆盖错误码。

所以现代运行库通常让 `errno` 变成每个线程一份，背后依赖线程局部存储 TLS。

## I/O 为什么要缓冲

如果每写一个字符都系统调用一次，性能会很差。

所以 `printf/fwrite` 通常先写到用户态缓冲区。缓冲区满了，或者遇到换行，或者你手动 `fflush`，才真正调用系统接口写出去。

这解释了很多现象：

- 程序崩溃前的输出可能没显示，因为还在缓冲区。
- 输出到终端和输出到文件，缓冲策略可能不同。
- `fflush(stdout)` 可以强制刷新。

## C++ 全局构造和析构

如果你写：

```cpp
class A {
public:
    A() { }
    ~A() { }
};

A global_a;
```

`global_a` 的构造函数要在 `main` 前调用，析构函数要在程序结束时调用。

这不是魔法。编译器和链接器会把构造函数地址放到某些表里，运行库启动时遍历这些表并调用。

## 全局对象初始化顺序问题

同一个文件里的全局对象构造顺序通常按定义顺序。

不同源文件之间的全局对象构造顺序不可靠。

如果 A.cpp 的全局对象构造时依赖 B.cpp 的全局对象已经构造好，就可能出问题。这就是经典的 static initialization order fiasco。

## fread 为什么值得分析

`fread` 看起来只是读文件，但里面可能做很多事：

- 检查参数。
- 给文件对象加锁。
- 判断缓冲区是否已有数据。
- 不够再调用底层 `read` 或 Windows `_read`。
- 文本模式下处理换行转换。
- 更新文件指针和状态。
- 返回实际读取的元素个数。

这说明运行库函数通常不是系统调用的简单一层壳。

## 文本模式和二进制模式

Windows 下文本模式可能把 `\r\n` 转成 `\n`，写的时候再反过来。

二进制模式不做这种转换。

所以处理图片、压缩包、二进制协议时，必须用二进制模式。

## 本章最重要的 takeaway

运行库负责把操作系统提供的底层能力整理成 C/C++ 程序能舒服使用的环境。`main` 前后的很多事情，包括堆、I/O、全局构造析构、退出清理，都不是凭空发生的。

## 建议动手实验

- 写全局对象，在构造和析构里打印，观察执行顺序。
- 使用 `atexit` 注册函数，看它什么时候执行。
- 用 `fflush` 对比缓冲输出效果。
- 在 Linux 下用 GDB 从 `_start` 跟到 `main`。

# E6 Linux BSP/驱动：启动链与真实器件

这是独立深化分支，前置为 [E5](../E5-BSP-Delivery/README.md) 的 C、硬件、调试与交付能力。它不自动继承 MCU API／任务模型，需要内核 C、地址空间、上下文、设备模型与镜像知识；当前没有 Linux BSP 或器件驱动实现。

## L1 从启动链到系统镜像

**先理解**：BootROM、U-Boot、kernel 与 rootfs 分别解决不同阶段的问题，实际启动链还可能包含厂商特定阶段。启动失败先定位发生在哪一层，不一律重编内核。

设备树描述硬件与绑定依据，不直接实现驱动。时钟、复位、IRQ、总线地址、pinctrl 等要与真板和 binding 对应；“节点存在”不表示 probe 已成功。

先选择有官方 BSP 和可恢复烧录方式的 ARM Linux 板。QEMU 可练习启动、构建和部分设备模型，但不证明真实引脚、电平、总线和 DMA 正确。

**独立练习**

1. 用官方 BSP 真板启动，解释启动日志、内核配置、设备树与 rootfs 的对应关系。
2. 选择 Buildroot 或 Yocto 之一固定版本，构建最小镜像；先复现官方路径，不同时更换所有组件。
3. 诊断一个自造配置问题，记录阶段、证据、恢复与回归。

## L2 设备与驱动怎样关联

**先理解**：device、bus、driver 与子系统有不同职责。匹配建立关联，probe 检查／初始化设备并建立资源；失败与解绑需要正确处理生命周期。

优先实现一个简单真实 I2C/SPI 器件，复用合适的子系统，例如传感器相关 IIO 或硬件监测相关 hwmon；不要为了“有驱动”先创造一套重复用户接口。

设备树 binding、ID、资源和依赖必须匹配。依赖未就绪可能需要延迟 probe，这不是默认成功；错误要按当前内核约定显式返回。

**独立练习**：核对匹配、probe、器件读写、错误路径和用户态访问；可按需要使用 regmap，仍需理解真实寄存器语义。字符设备 hello-world 或用户态串口程序不足以证明器件驱动能力。

## L3 上下文与异步生命周期

**先理解**：进程上下文、硬中断、持锁和其他原子上下文允许的操作不同。可能睡眠的分配、锁、IO 与等待不能随意放到原子上下文；锁的实际语义还要结合内核配置与版本。

解绑／卸载前应停止数据来源，并处理 IRQ、work、timer、DMA、用户请求等异步访问。受管理资源释放不自动意味着所有回调都已停止，不能让回调访问已释放对象。

**独立练习**：在自己的板卡／隔离 VM 中验证初始化失败、依赖缺失、超时、并发访问与绑定／解绑；回归无泄漏、悬空访问和无界等待。硬件不支持热插拔时，不把软件解绑等同于物理热插拔验证。

## L4 地址与 DMA 不能照搬 MCU

**先理解**：CPU 虚拟地址、物理地址与设备使用的 DMA／总线地址不总相同；IOMMU 和平台映射可能介入。不能把普通指针或物理地址直接当作设备 DMA 地址。

MMIO 和 DMA 使用当前内核规定的访问、映射、同步与生命周期 API；传输方向、设备能力、ownership、cache 和内存区域约束都要核对。MCU 的缓存维护与地址经验不能替代 Linux DMA API。

DMA 是后续条件专项，不要求第一个 I2C/SPI 驱动就展开。实施时先阅读所选内核文档并确认硬件支持，再给出真实传输与错误恢复证据。

## 验收与回看

- 真板启动可复现，工具链、镜像、配置、设备树与硬件版本对应。
- 真实器件完成匹配、probe、读写与用户态访问，资源／错误清理明确。
- 有一次独立定位与回归，软件解绑等测试只在自己的设备／隔离环境执行。
- QEMU、用户态 demo、静态阅读、真实器件与 DMA 证据分别标记，不互相替代。

复述一条启动链、一个设备绑定依据、一项上下文限制和一次异步清理。记录 [进度](../../Progress.md)，不声称完成全部 BSP 或内核子系统。

# E6 教学：按岗位选择一个深化分支

前置：[E5](../E5-BSP-Delivery/README.md) 的项目与交付证据。默认继续 MCU/BSP；如果目标明确是 Linux BSP／驱动，再展开独立分支。不用“嵌入式”泛称掩盖两类岗位的差别，也不同时把所有方向设为必修。

## 分支与最低证据

| 分支 | 正文 | 核心变化 | 验收重点 |
| --- | --- | --- | --- |
| MCU/BSP | [板级移植与升级](MCU-BSP.md) | 从单板运行走向配置移植，按需理解镜像与失败恢复 | 真板移植，或明确故障模型的升级恢复 |
| Linux BSP/驱动 | [启动链与器件驱动](Linux-BSP-Drivers.md) | 从 MCU 固件转向内核、设备树、镜像与驱动子系统 | 真板启动、真实器件、绑定／解绑与错误清理 |

两者共享 C、硬件接口、调试和资源意识，但 API、地址空间、调度、驱动模型与构建链不同。MCU 的寄存器控制不等于 Linux 驱动；Linux 用户态串口程序也不等于 BSP 或内核驱动。

当前仅提供教学。后续实现放在本模块 `practice` 中，再按分支组织工程；不创建空代码目录或伪造验证状态。

## 按岗位添加选修

| 选修 | 先理解 | 最小实践与边界 |
| --- | --- | --- |
| CAN/CAN FD | 帧、仲裁、位时序、终端与收发器、错误计数／bus-off、经典 CAN 与 FD 差异 | 自有隔离总线通信、错误与恢复；不连接真实车辆或公共总线 |
| UDS/DoIP | 诊断请求／响应、会话、超时、传输分段、网络与应用层边界 | 公开／自造诊断端点；协议熟悉与真实栈适配分开 |
| AUTOSAR Classic | 分层、RTE、BSW、MCAL、配置生成、OS 与通信／诊断边界 | 在合法可用工具／公开材料范围内做一个配置或适配专项；不把架构阅读称为完成移植 |
| 低功耗 | 时钟门控、睡眠状态、唤醒源、外设／DMA 状态与恢复 | 额定实验条件下测功耗与唤醒后功能；不只报告睡眠电流 |
| 安全启动 | 镜像认证、信任根、密钥管理与回滚保护 | 优先研究成熟方案与威胁模型；CRC 不替代签名，不能随意自研认证协议 |
| 功能安全 | 故障模型、诊断覆盖、追踪与验证流程 | 学习原则与证据组织，不宣称满足标准或完成认证 |

选择依据是公开岗位要求或项目实际缺口。AI／CUDA、完整数据库、多种 RTOS 和复杂车载软件栈不作为通用前置，不为增加名词同时展开。

## 独立复述与求职表达

- 用公开岗位描述解释选定分支及未展开的部分。
- 能讲一次启动／移植或驱动错误的根因与证据，而不是只列工具名称。
- 区分已阅读、已实现、host 已测、真板已测与声明负载已测。
- 学习项目如实说明自己的贡献，不编造量产规模、内部经历或业务收益。

未完成分支真板证据时保持待验证；能力记录使用 [进度](../../Progress.md)，不因为正文齐全就升级状态。

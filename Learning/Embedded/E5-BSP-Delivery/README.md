# E5 教学：BSP、可靠性与交付

前置：[E4 真板链路](../E4-Data-Acquisition/README.md)。目标是把“能运行一次”变成可构建、可诊断、可复现的工程证据，不宣称完成量产可靠性。当前没有新增 BSP、部署脚本或长测结果。

## L1 BSP 是边界不是万能抽象

**先理解**：板级配置负责与具体硬件绑定的启动、时钟、引脚和资源；驱动提供外设合同；RTOS 适配处理上下文与调度；协议／策略尽量不依赖具体寄存器。

只抽取当前有实际变化的边界，避免为所有潜在芯片创建大量接口。反过来，把任务业务、寄存器和协议混在一个回调里，会使替换板卡与定位错误困难。

**独立练习**

- 把 E4 的依赖分为 host 可测策略、RTOS 适配、器件驱动和板级配置，画出真实调用关系。
- 选择一个小型板级变化，说明影响范围，不重写全部系统。
- 固定工具链、CMSIS／厂商包、FreeRTOS、驱动、编译链接选项与配置来源，保留版本和许可信息。

构建产物至少包括固件／ELF、map、配置与版本、烧录步骤及所用工具。警告与错误要显式处理，不靠“换另一份预编译二进制”伪装源码可复现。

## L2 复位与看门狗要有业务含义

**先理解**：复位可能来自软件、看门狗、供电或其他硬件原因。它能恢复部分状态，也可能丢失数据与现场，不能把重复复位当作问题已解决。

看门狗应检测关键任务进展，而不是只证明某个定时中断还能运行。合法阻塞、低功耗和启动阶段也要在规则中定义，避免错误重启。

窗口看门狗或不同硬件有各自喂狗时序要求；brown-out 阈值与恢复行为以芯片为准。不要凭通用教程设置电压、超时或寄存器。

**独立练习**

1. 让一个关键任务受控停滞，核对检测、复位及重启后的原因记录。
2. 用慢 IO 与合法空闲验证不会误判；说明在极端负载下的检测边界。
3. 验证重启后的初始化、外设状态与数据丢失合同；诊断记录若不可靠，明确指出。

## L3 验证矩阵与交付产物

**先理解**：单元、交叉构建、真板集成、时序、故障与长测验证不同问题，不能互相代替。调试／Sanitizer／Release 配置也不能混为同一种性能证据。

| 场景 | 主要核对 |
| --- | --- |
| 空闲与正常负载 | 功能、资源基线、合法等待与恢复 |
| 满负载、突发与持续过载 | 超期、容量、错误策略、诊断干扰 |
| 器件失败与通信错误 | 有限恢复、错误返回、下一次调用状态 |
| 任务停滞与软件／看门狗复位 | 检测、原因、初始化与数据边界 |
| 存储断写（若实现） | 有效记录识别、恢复与确认合同 |

先定义负载、输入大小、测量方法、运行时间与可接受结果，再执行实验。E5 至少做一次 2 小时真板稳定负载测试与一次过载测试，记录资源趋势；这不是量产可靠性证明。

**交付练习**

- 在另一份干净、可控环境构建并烧录同一版本，记录配置与产物对应；没有第二环境就保留待验证。
- 提供健康状态、正常启动／停止、错误恢复和排障入口，健康检查不能只判断固件还有输出。
- 完成两个故障定位案例和一个资源／时序优化案例，保存同条件对比，结果无提升也如实说明。
- 回归原有行为，不以关闭错误检测、减少必需功能或静默丢弃换取漂亮性能。

## 阶段验收与回看

- 小型 BSP 与实际依赖边界明确，可解释板级变化影响。
- 固件、配置、map、版本与烧录步骤可复现，原始资料与依赖可追踪。
- 关键任务停滞可被检测，合法等待不被随意当作故障；恢复结果符合合同。
- 声明负载下的长测／过载、诊断与回归证据完整，未测部分明确。

复述检查：解释一次停滞、一项复位边界、一项 BSP 改动和优化代价。E5 有证据后可进行编码、手册阅读、项目深挖模拟与定向试投递，不等待全部选修；深化选择见 [E6](../E6-Specialization/README.md)。

维护与记录方式见 [课程入口](../README.md)，岗位与试投递标准见 [路线图](../../Embedded-Roadmap.md)。本课不处理无关的既存 host 平台问题，也不将课程文档标记为实测结果。

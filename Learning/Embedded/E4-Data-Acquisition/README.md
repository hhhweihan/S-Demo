# E4 教学：有界采集与诊断固件

前置：[E2 外设](../E2-Peripherals-DMA/README.md) 与 [E3 RTOS](../E3-FreeRTOS-Realtime/README.md)。本阶段把组件串成一个小型真板代表作，不同时建设云平台、复杂 UI、数据库或分布式系统。当前只有教学，固件与实验尚未实现。

## L1 先定义合同再画架构

**先理解**：架构要服务于输入、资源、时间和可靠性约束。先确定一种输入、一条处理链路和一种输出，而不是先列技术栈。

```text
真实传感器或实验设备
  -> 驱动与有界输入缓冲
  -> 解析/校验任务
  -> 有界事件交付
  -> 输出任务
  -> UART 导出；有条件再加入 Flash
```

区分“接收成功”“处理完成”“输出完成”“持久化完成”的确认点。入队确认后复位可能丢失数据；输出驱动完成不自动等于存储持久化。

**独立练习**：写协议字段、唯一事件标识的范围、编码与长度上限、采样周期、超时、过载策略、错误响应和复位丢失边界。标识如果会在重启后重复，应加入可解释的会话范围。

每个接口明确：数据是复制还是借用，谁持有、何时归还、失败是否已消费、何时允许重试。不能把 E0 的临时视图直接传给异步任务后立即复用输入。

## L2 容量与数据核对

**先理解**：队列有界不等于整个系统内存有界。连接／输入缓冲、任务栈、输出暂存、驱动描述与运行时同样占资源；批处理也需要预算。

| 预算项 | 需要填写 |
| --- | --- |
| 输入速率与事件大小 | 来源、峰值、最大长度与突发模型 |
| 每段缓冲 | 容量、生命周期、生产／消费关系 |
| 任务与 ISR | 栈、优先级、时间预算、阻塞来源 |
| 输出与保留 | 速率、超时、保留空间与失败策略 |
| 总体资源 | map、运行栈／堆证据与安全余量依据 |

过载可选择拒绝、丢弃、降采样或阻塞等，但必须符合上下文和可靠性合同；ISR 中无界等待不是背压方案。任何允许丢弃的路径都应有计数与可解释范围。

在同一运行会话、停止输入并排空后，用事件 ID 核对互斥终态：`accepted = completed + explicitly_failed_or_dropped`。运行中还要单独解释排队与处理中事件，拒绝事件另计。重试、重复与重启不能混入计数制造“无丢失”；测试核对不等于 exactly-once 承诺。

**独立练习**：正常输入、突发与持续过载各核对一次；检查队列峰值、丢弃／拒绝、完成与失败，而不只报告处理速度。

## L3 诊断不能成为新的故障源

**先理解**：诊断输出本身有 CPU、缓冲、锁和 IO 成本。大量串口打印可能改变调度与测量结果，fault 中调用复杂输出还可能再次出错。

最小诊断应能说明固件版本、复位原因、错误计数、队列水位、栈水位和可安全捕获的 fault 现场。明确何时采样、谁更新、捕获失败怎样报告，不假定 fault 时所有栈与资源仍可用。

**独立练习**

1. 注入慢输出、器件缺失、输入超速与任务超期，观察结果与计数。
2. 制造受控软件 fault 或任务停滞，说明捕获到的证据与未能捕获的部分。
3. 比较诊断开启／降低输出时的资源和时序，避免把诊断干扰当作业务瓶颈。

## L4 持久化是可选的第二条链路

没有真实 Flash 器件或存储合同时，先完成 RAM 与 UART 闭环，不虚构持久化结果。

**先理解**：Flash 的擦除粒度、写入限制、耗时、寿命和完成状态由器件规定。记录必须有可识别的完整性与提交规则，写入中断后不能把部分数据当作有效记录。

CRC 只能支持相应损坏检测，不是密码学认证，也不自动实现原子写入。磨损分布、日志回收和复位恢复都需要单独设计与实测。

**独立练习**：在实际器件上记录“开始写／完成／确认”的顺序；对可控断写或复位模型验证扫描、损坏记录、保留有效数据与恢复边界。供电测试仅在额定范围和专用实验条件内进行。

## 阶段验收与回看

- 真板端到端闭环可复现，协议、状态、数据标识、任务与资源预算明确。
- 正常、过载、错误和退出／复位结果符合合同，数据无未解释缺口。
- 诊断与时序证据能支持结论，计数范围、测量开销和局限有记录。
- 如加入 Flash，有真实介质与恢复证据；RAM 模拟只说明策略，不说明持久化。

# E1 教学：C、受限 C++、启动与调试

前置：[E0 教学](../../00-Embedded-Start/Byte-Ring-Guide.md) 与 [帧解析](../../00-Embedded-Start/Frame-Parser-Guide.md)。本阶段先做 host 语言边界，再追踪交叉构建、启动与异常。代码未来放在本模块的 `practice` 中；当前未创建固件或真板实验。

## L1 指针与整数边界

**先理解**：指针表达地址，不表达长度、所有权或对象生命周期。数组在许多表达式中退化为指针，调用者传来的指针与大小是一份合同，不能用函数内的指针 `sizeof` 推导原数组长度。

整数运算要同时考虑类型、提升、符号、宽度和中间结果。转换后再检查可能已经丢失信息；越界访问、非法移位、部分有符号溢出属于未定义行为，不能以“这次看起来能运行”判断正确。

内存布局也不等于协议布局：结构体有对齐与填充，任意缓冲不保证满足目标类型对齐。把字节流映射为结构体或整数指针，需要证明端序、对齐、对象与别名条件，通常不应作为解析捷径。

`const` 限制相应访问方式，不自动让所有别名都只读，也不自动决定对象放在 Flash。`volatile` 约束编译器对相关访问的处理，常用于有特殊访问语义的寄存器；它不自动保证原子性、跨上下文同步或 cache 一致性。原子操作、临界区、硬件屏障和缓存维护解决的问题不同，不能互相替代。

**独立练习**

1. 回到 E0，列出输入长度、容量与索引的所有边界和中间计算。
2. 用公开／自造小例子诊断悬空指针、数组退化、长度截断或未对齐访问，分别说明可检测与不可保证检测的情况。
3. 使用 host 测试／Sanitizer 形成最小复现与回归；不要添加掩盖非法输入的默认成功返回。

**检查点**：能解释地址、长度、生命周期、对齐各由谁保证；未复现 UB 不表示它不存在。

## L2 受限环境中的 C++

**先理解**：RAII 把资源释放绑定到正常 C++ 控制流与析构，不意味着复位、断电或硬件 fault 一定会执行清理。移动表达所有权转移，非拥有视图仍受底层对象生命周期约束。

嵌入式成本包括 Flash、RAM、初始化、栈、堆、执行时间和所需运行时。模板不等于必然零代码尺寸成本，虚函数不等于一律不可用，标准库也不等于全部分配。要观察所选实现与实例化。

为一个具体工程制定异常、RTTI、动态分配、容器和日志规则。关闭特性之前确认依赖能否使用、错误如何传播、ABI 是否一致；不能简单删掉运行时链接后把未定义符号当作编译器问题。

**独立练习**

- 比较一个固定容量结构与动态容器的目标产物，记录配置、map 和使用路径，不以 host 性能代替 MCU 成本。
- 写清初始化后是否允许分配、分配失败如何显式传播；检查标准库调用是否符合规则。
- 解释一次对象构造、移动与析构，以及它在异常、正常退出与复位中的边界。

复习素材：[内存管理](../../01-内存管理/README.md)、[模板](../../03-模板泛型/README.md)、[容器](../../04-STL-Sequence/README.md)。现有 host 根构建仍为 C++20，MCU 标准按工具链和运行时选择，不为本课升级或降级根构建。

## L3 从源码到内存布局

**先理解**：预处理、编译、汇编、链接解决不同问题。ELF 包含符号与段等信息，烧录镜像不等于全部 ELF；map 用于解释符号、段、丢弃内容和内存预算。

- Flash/RAM 是存储资源；`.text`、`.rodata`、`.data`、`.bss` 是链接布局概念，具体放置由链接脚本决定。
- 常见固件中 `.data` 的初值在 Flash，运行对象在 RAM，体现装载地址 LMA 与运行地址 VMA 的区别。
- `.bss` 需要运行时清零，占 RAM，但不要求镜像逐字节存储全部零。
- 向量表、启动代码与初始化数组即使没有普通调用路径也可能必须保留；理解链接垃圾回收与保留规则。
- ABI、调用约定、浮点选项和运行时库必须相容；“目标能链接”也不自动证明行为符合约束。

**独立练习**：交叉构建官方最小工程，使用 `size`、`nm`、`objdump` 与 map 找到至少一个函数、常量、已初始化变量和零初始化变量，说明它们的尺寸、位置与初始化来源。

**检查点**：能区分编译错误、链接错误和运行错误；静态 map 不包含全部峰值栈／堆开销。

## L4 Cortex-M 启动与异常

**先理解**：沿所选芯片的 reset 路径追踪初始栈与向量、时钟初始化、数据初始化、C++ 初始化到 `main`。不能假定改写了 reset handler 后厂商支持包还会自动完成所有运行时步骤。

异常涉及硬件现场与软件保存的上下文。MSP/PSP、异常入口／返回、任务上下文与栈预算要对照所选核心、ABI 和 RTOS port。发生 fault 后先收集 PC/LR、现场栈和该核心支持的状态寄存器，再沿符号与反汇编定位。

并非每个 Cortex-M 都有相同 fault 寄存器、BASEPRI、优先级分组、FPU、MPU、DWT 或 D-cache。先确认核心与芯片能力；不要照抄 M4/M7 诊断和临界区代码到 M0/M0+。

**独立练习**

1. 真板下断点，追踪启动并把变量地址与 map 对应起来。
2. 在专用实验板制造一个可控软件 fault，保存现场，给出最小根因和回归方法；不以“重启恢复”结束分析。
3. 做一项小型链接／板级配置修改，验证启动、变量初始化和布局没有被破坏。

## 阶段验收与回看

- host 边界问题有最小复现与回归，能独立说明所有权和整数边界。
- 能解释 ELF、map、LMA/VMA、初始化和运行时依赖。
- 真板能调试启动并定位一个自造 fault，证据与具体核心对应。
- 无开发板时可先完成 host 和资料阅读，启动与异常项保持待验证。

常见误区：`volatile` 不是同步；map 小不表示运行时不会溢出；RAII 不保证复位清理；优化构建中的调试现象不能只按源码行顺序解释。

复述时说明一个语言错误、一个启动依赖和一个故障证据链，再进入 [E2](../E2-Peripherals-DMA/README.md)。记录格式见 [课程入口](../README.md)。

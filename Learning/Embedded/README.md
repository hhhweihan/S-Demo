# 嵌入式课程：从 host 合同到真板交付

这是 [嵌入式能力路线](../Embedded-Roadmap.md) 的教学正文。路线图说明“学什么、何时验收”，本课程解释“为什么、怎样逐步练习、如何判断结果”。目标是独立理解、实现、排障和验证，不是记完名词或复制固件。

## 文档与代码怎样放

- E0 的任务、两篇教学与 [现有练习](../00-Embedded-Start/practice/embedded_basics/README.md) 保留在同一模块，不再次搬动代码。
- E1–E6 的正文位于本目录的各阶段模块；以后新增实现放在对应模块的 `practice` 中，接口、代码、测试与模块说明一起维护。
- 当前只有 E0 的 host 练习骨架；本轮补齐教学文档，**不表示后续固件、驱动、测试或硬件实验已经存在**。
- 不提供环形缓冲／解析器的完整实现、寄存器配置答案或可直接烧录的完整固件；例子只用于解释合同和现象。
- 各模块“常见误区”用于回看；“独立复述检查”不附答案，应结合自己做过的实验说明。

## 每课的学习闭环

1. **阅读概念**：先理解对象、资源、时序和失败语义，遇到具体寄存器或 API 再查原始资料。
2. **写合同**：列输入、输出、前置条件、不变量、容量、超时和所有权。
3. **最小练习**：一次只改一个可验收点；先正确、后优化，不一开始扩成通用框架。
4. **验证**：用对应测试、手册、map、波形、异常现场或测量解释结果。
5. **闭卷复述**：说明关键机制、一个失败场景和一个替代方案，再更新 [进度](../Progress.md)。

记录格式：`课号 / 独立完成部分 / 板卡与软件版本 / 验证入口 / 结果 / 已知限制 / 下一步`。阅读完成可以记录，但不能升级为“已掌握”；文档有了也不能代替实现和证据。

## 证据分层

| 证据 | 可以支持的结论 | 不能直接支持的结论 |
| --- | --- | --- |
| host 单元测试／Sanitizer | 已执行输入与逻辑边界，发现对应内存错误的能力 | MCU 中断、DMA、实时性和电气正确性 |
| 交叉编译、ELF 与 map | 当前目标能构建，静态布局和固件尺寸可解释 | 真板能启动、峰值栈够用 |
| 真板调试、总线波形 | 声明配置下的外设与异常行为 | 所有负载、所有芯片都正确 |
| 时序、压力与长测 | 声明负载、测量时长内的观测结果 | 严格 WCET、量产可靠性或功能安全认证 |
| 复位／断写恢复 | 已测试故障模型下的恢复边界 | 所有断电、介质故障或 exactly-once |

涉及硬件特性的判断必须记录具体芯片、核心、支持包、RTOS port 和版本。不能把 Cortex-M4/M7 的寄存器、缓存或临界区方式直接套到所有 Cortex-M。

## 社招能力如何映射

- **编码**：在约定时间内独立实现边界明确的 C 接口，说明容量、错误与复杂度。
- **手册阅读**：从未知外设的时钟、引脚、状态位和时序找到可验证的配置依据。
- **排障**：从现象提出假设，收集现场，缩小根因，修复后补回归。
- **设计与交付**：讲清资源预算、任务结构、失败合同、版本和复现方法。
- **表达**：准备一个项目的短概览、深入追问，以及两个排障／一个优化案例；学习项目如实标注，不编造线上经历或收益。

E5 后按匹配度开始定向模拟与试投递；BSP／驱动岗位另需相应 E6 深度。CUDA、AI 推理、复杂 AUTOSAR 或多种 RTOS 不是通用前置，选修应由岗位要求或实际瓶颈驱动。

## 资料与边界

正文是学习解释，原始合同以当前 [练习说明](../00-Embedded-Start/practice/embedded_basics/README.md)、所选芯片手册与对应官方文档为准。记录资料版本和未确定项，不把 AI 给出的寄存器、优先级或持久化结论直接视为事实。

只使用公开／自造材料，不写个人履历和敏感背景，不引入内部代码、凭证或业务数据。硬件实验仅在自己的低压板卡与隔离环境进行，不连接真实车辆、公共总线或生产设备。

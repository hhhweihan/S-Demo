# E0 起步任务：先诊断，再进入真板

## 本模块实践

- [embedded_basics](practice/embedded_basics/README.md) · [测试](practice/embedded_basics/tests/)

本页将 [嵌入式路线 E0](../Embedded-Roadmap.md#e0岗位校准与实验环境) 拆成可以逐项执行的任务，不提供练习实现答案，不设期限。尚无开发板时先做公开岗位校准、host 环境和独立编码；真板验收保持待验证。

## 教学阅读入口

1. [环形缓冲教学](Byte-Ring-Guide.md)：逻辑队列、状态、所有权、错误合同与分步检查；先独立完成初始化。
2. [帧解析教学](Frame-Parser-Guide.md)：字节序、输入边界、分片与视图；缓冲验收后再推进。
3. [完整课程](../Embedded/README.md) 与 [知识地图](../Embedded/Knowledge-Map.md)：回看 E1–E6 的概念、练习和证据条件，不同时展开全部选修。

## 任务顺序

| 任务 | 操作 | 留下的证据 | 完成条件 |
| --- | --- | --- | --- |
| E0-01 岗位校准 | 阅读 5–10 份公开职位描述，分 MCU/RTOS、MCU BSP、Linux BSP/驱动；先选一种主投类型 | 公共链接、必需／加分技能分类、前三个缺口 | 每个缺口都有对应练习，不凭职位名称判断能力 |
| E0-02 host 环境 | 打开 [embedded_basics](practice/embedded_basics/README.md)，配置、构建并运行初始验收 | 编译器版本、构建结果、测试失败原因 | 工程能编译；确认失败来自未实现状态，而非环境错误 |
| E0-03 字节环形缓冲 | 独立完成 init/push/pop，先容量 1，再容量 3 和回绕 | 实现、5 个验收用例结果、不变量说明 | 全部缓冲用例通过，无分配、无覆盖、失败不破坏数据 |
| E0-04 有界帧解析 | 独立实现长度字段帧解析，处理分片、非法长度、参数和视图 | 实现、5 个验收用例结果、生命周期说明 | 全部解析用例通过，能说明每种失败时的读取边界 |
| E0-05 口头与手册诊断 | 回答下方问题，查一份具体芯片手册 | 自己的答案、手册章节和未确定项 | 不借助 AI 解释；不确定之处有查证路径 |
| E0-06 选板与真板环境 | 按选板条件确认型号，完成官方最小工程与断点调试 | 型号、资源、引脚依据、构建烧录与调试结果 | 真板构建、烧录、单步与寄存器查看均完成 |

前三个缺口必须由诊断得出，不能预先把“没有开发板”当作全部技术短板。仅创建练习或阅读任务不等于这些任务已经完成。

## 独立诊断问题（不附答案）

1. 返回输入缓冲内部指针后，调用者释放、复用或改写缓冲，各会发生什么？接口如何表达生命周期约束？
2. 长度来自不可信输入时，如何防止读取越界和长度计算溢出？为什么“先读，再检查”不成立？
3. 环形缓冲容量为 1 或 3 时，满、空与回绕如何区分？如果满时失败，应保留哪些状态？
4. `volatile` 能否使 ISR 与任务共享的环形缓冲自动正确？哪些更新可能被中断打断，需要补充哪些约束？
5. host 用例全绿之后，为什么仍不能证明 DMA 缓冲和 RTOS 调度正确？板上还应测什么？
6. 从一份公开芯片手册查出 UART 时钟来源、引脚复用和中断；说明每条结论的章节依据，而不是复述 HAL 调用名。

## 开发板选择条件

第一阶段默认 Cortex-M + FreeRTOS。优先选择资料完整、有板载 SWD 调试器的 STM32 Nucleo 或同类开发板，先核对具体型号，不根据系列名直接购买。

| 必须核对 | 判断依据 |
| --- | --- |
| 调试链路 | 板载调试器、USB 接口、SWD 连接、官方驱动与调试文档可用 |
| 基本资源 | UART、定时器、I2C/SPI、DMA、看门狗及可用引脚满足后续练习 |
| 存储资源 | datasheet 的 Flash/RAM 容量能容纳所选官方 FreeRTOS 示例与应用预算 |
| 原始资料 | datasheet、reference manual、errata、板卡原理图和 user manual 对应具体型号 |
| 软件支持 | 官方最小工程、CMSIS/厂商支持包和 FreeRTOS 移植可复现，版本可固定 |
| 电气条件 | 电平、供电、上拉、接口复用明确；只接兼容的低压实验器件 |

开始只需要板卡、合适的 USB 线和 host；传感器、SPI Flash、逻辑分析仪随 E2 的具体任务再选。CAN 控制器／收发器、ARM Linux 板或复杂调试设备不作首轮采购前置。购买后先核对型号与资料，不连接实际车辆或生产设备。

## 环境边界

- host C/C++ 编译器用于本组逻辑练习；Arm 交叉编译器用于后续 MCU 固件，两者不可互换。
- 本组是独立工程，不改变原有 18 个模块与默认 CI；测试使用仓库已固定的 GoogleTest 版本。
- 便携工具可以用于起步验证；长期开发应固定可复现的工具链位置与版本，不依赖临时会话路径。
- 无开发板时 E0-01 至 E0-05 可先推进；不能将仿真／host 结果升级为 E0-06 真板通过。

## 完成后怎么回填

E0-03/E0-04 通过后先做一次闭卷解释，再进入 [E1](../Embedded/E1-Language-Startup/README.md)；E0 整体只有在岗位诊断和真板环境也验收后才能完成。允许先学 E1 的 host 部分，但启动、fault 和时序项仍须等待板上证据。

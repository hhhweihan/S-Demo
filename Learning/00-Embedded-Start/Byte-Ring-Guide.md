# E0-03 教学：固定容量字节环形缓冲

前置：[E0 起步](README.md)。接口、完整合同和构建入口见 [练习说明](practice/embedded_basics/README.md)；待实现文件是 [byte_ring.c](practice/embedded_basics/byte_ring.c)，测试是 [embedded_basics_tests.cpp](practice/embedded_basics/tests/embedded_basics_tests.cpp)。本页讲机制与检查方法，不给实现答案。

## L1 先区分逻辑队列与物理存储

环形缓冲借助固定存储反复使用槽位，读写到末尾可以回绕。逻辑队列仍保持 FIFO，不因物理位置变化而改变顺序。

| 容量 3 的操作 | 逻辑队列／结果 |
| --- | --- |
| 依次放入 10、20、30 | 10、20、30 |
| 再放入 40 | 拒绝，原数据不变 |
| 取出一个字节 | 得到 10，剩余 20、30 |
| 放入 40 | 20、30、40 |

取出元素不要求清零原槽位，只要它不再属于有效数据。不能用“槽位的值是零”判断空：零本身也是合法输入。

本练习使用全部容量，不预留一个槽位，也不限制容量为 2 的幂。容量 1 与容量 3 是重要检查点，不只是特殊情况。

## L2 对象保存什么状态

阅读 [ByteRing 接口](practice/embedded_basics/byte_ring.h)：

| 字段 | 职责 |
| --- | --- |
| `storage` | 借用调用者的存储，不申请、不释放 |
| `capacity` | 可容纳的字节数量，成功初始化后大于零 |
| `read_index` | 下一次出队使用的物理位置 |
| `size` | 当前有效元素数量 |

成功初始化后的不变量：

- 有效元素数量在零与容量之间；零表示空，达到容量表示满。
- 读取位置处于可用范围内。
- 元素顺序与成功入队／出队历史一致。
- 调用者提供的存储仍有效，且不与对象重叠。

接口没有保存独立写入索引。先画状态变化，再独立推导写入位置；索引计算必须考虑边界与中间算术，不能认为“最后取模”自动解决所有问题。

## L3 错误状态也是合同

| 情况 | 返回／行为 |
| --- | --- |
| 合法初始化 | 成功，建立空队列 |
| 空对象／存储或零容量 | 参数错误，不改变已有对象 |
| 成功入队 | 增加一个有效字节 |
| 满时入队 | 返回满，不覆盖、丢弃或偷偷扩容 |
| 成功出队 | 写出一个字节并消费它 |
| 空时出队 | 返回空，输出参数与对象不变 |
| 出队输出指针为空 | 参数错误，不消费已有数据 |

错误返回必须由调用者处理，不能当作成功继续使用输出。无效参数可以检查，已经悬空的非空存储指针不能靠这个 API 自动识别；生命周期是调用者前置条件。

## L4 分步实现与检查

| 步骤 | 本次只推进 | 自检与测试观察 |
| --- | --- | --- |
| 1 | 初始化 | 修改状态前完成参数检查；合法调用为空；非法调用保留原状态 |
| 2 | 空队列出队与参数检查 | 空返回不改输出；参数错误不消费数据 |
| 3 | 基本入队／出队 | 单字节、多字节、零与 255；FIFO，每次只处理一个元素 |
| 4 | 满队列拒绝 | 用满全部槽位；拒绝额外输入后旧数据仍能依次取出 |
| 5 | 回绕与重复使用 | 容量 1、容量 3，反复交替入队出队不丢失顺序 |

先完成步骤 1，保留其余占位接口。此时测试可能从“初始化失败”推进到“入队／出队未实现”，属于正常反馈，不能因此删测试或提前宣称通过。

现有五个缓冲用例分别验证：空出队输出保护、满容量与拒绝、非 2 的幂容量回绕、容量 1 重用、无效参数不破坏状态。只运行 `embedded_byte_ring`，全部通过后再进入 [帧解析教学](Frame-Parser-Guide.md)。

## L5 从 host 到 MCU 还差什么

当前实现是单线程合同，没有线程／ISR 同步。把它接到中断或 DMA 前，还需要确定生产者、消费者、共享字段、更新交错、缓冲交接与过载策略。

`volatile` 不会自动使多步状态更新成为原子操作。环形索引正确也不能阻止 DMA 覆盖尚未消费的数据。后续分别在 [外设课程](../Embedded/E2-Peripherals-DMA/README.md) 和 [RTOS 课程](../Embedded/E3-FreeRTOS-Realtime/README.md) 建立新的合同与板上测试。

- 能说明每一种失败必须保持的对象与输出状态。

# E0-04 教学：长度字段有界帧解析

前置：[环形缓冲教学](Byte-Ring-Guide.md)。当前接口在 [frame_parser.h](practice/embedded_basics/frame_parser.h)，待实现处为 [frame_parser.c](practice/embedded_basics/frame_parser.c)，合同与验证入口见 [练习说明](practice/embedded_basics/README.md)。本课不提供解析实现。

## L1 协议字节不等于内存对象

练习线协议为两字节大端长度，后面跟 0–32 字节 payload。例如 `00 03 11 22 33` 的 payload 是三个字节，总帧长是五个字节。

大端规定高有效字节先出现，不由 host 的端序决定。不能只读取低字节，也不能把任意输入地址强转成整数指针：对齐、别名、端序和可读范围都可能不满足。

长度来自不可信输入。先判断此时可读范围，再读取字段；在长度合法后才考虑 payload 是否到齐。固定上限是资源合同，不是“不检查长度也不会出问题”的理由。

## L2 四种结果必须分开

| 情况 | 结果 |
| --- | --- |
| 参数满足前置条件，第一帧完整 | `FRAME_OK`，返回第一帧视图和实际消费长度 |
| 尚无输入、头未完整、合法 payload 未完整 | `FRAME_INCOMPLETE`，等待更多输入 |
| 完整头声明长度超过 32 | `FRAME_INVALID_LENGTH`，立即拒绝，不继续等待超大 payload |
| 输出指针为空，或输入为空但输入大小非零 | `FRAME_INVALID_ARGUMENT`，参数检查优先 |

除成功外，所有可用输出与 `consumed` 保持原值。`input == NULL && input_size == 0` 表示尚无输入，不等于零长度 payload；零长度帧仍必须含有完整头。

## L3 解析与流式累积是两层

当前函数只解析调用者交来的连续输入，不负责缓存。只消费第一帧，多帧合并到达时，调用者根据成功返回的长度继续处理剩余输入。

分片到达时，调用者保留不完整前缀，收到后续字节后重试；不能将每次串口回调或 TCP 读取都视为完整帧。缓存本身要有上限、超时和错误策略，这些属于后续链路合同。

本协议没有同步标记和 CRC，**不自动提供噪声后的重新同步或数据损坏检测**。遇到非法头不能猜测“跳一个字节就能恢复”；UART 生产协议需要另行设计同步、校验与恢复方式。

## L4 返回视图的生命周期

成功返回的是指向输入内部的非拥有视图，不复制 payload、不分配内存。它借用的是输入的生命周期。

- 输入被释放、复用或改写后，不能继续按原视图使用数据。
- 零长度帧的 payload 指向头之后的位置，不能解引用。
- 输入与输出对象不重叠，传入大小描述可访问内存，由调用者保证。
- 把视图跨任务传递时必须建立所有权或复制策略；“指针已经进队列”不等于 payload 被复制。

## L5 分步推进

| 步骤 | 独立任务 | 检查点 |
| --- | --- | --- |
| 1 | 写结果分类和读取边界 | 列出每种失败时已经能安全读取的字节，不先读后查 |
| 2 | 参数与不完整输入 | 参数错误优先，空输入、单字节头、截断 payload 保留输出 |
| 3 | 大端长度与上限 | 零、32、33、仅高字节非零与最大长度，不能截断字段 |
| 4 | 成功视图与消费长度 | 地址、payload 大小与总消费长度准确，尾随输入不被消费 |
| 5 | 生命周期复述 | 说明何时可以回收输入，以及下一层怎样累积分片 |

只运行 `embedded_frame_parser`。五个现有用例覆盖第一帧与尾随数据、零／最大 payload、不完整输入、非法大端长度、参数与输出保护；全部通过只表示当前 host 合同通过。

## 常见误区与独立复述检查

- “收到若干字节”不等于“收到一个应用帧”。
- `INCOMPLETE` 是等待数据的状态，不是成功，也不是所有异常的统一结果。
- 超大长度不能通过等待更多输入解决；必须服从资源上限。
- 返回视图不拥有输入；状态成功不延长输入生命周期。
- 测试全绿不能证明串口噪声、DMA 覆盖或任务并发正确。

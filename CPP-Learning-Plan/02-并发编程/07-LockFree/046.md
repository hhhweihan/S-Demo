## tagged pointer 的作用

最直接的办法，是把“指针值”和“版本号”一起参加 CAS：

```cpp
struct TaggedPtr {
    Node* ptr;
    std::uintptr_t tag;
};

std::atomic<TaggedPtr> head_;
```

每次 pop 成功后，不只是把 `ptr` 改成 `next`，还要把 `tag` 加一。这样即使地址后来又回到了原值，只要版本号不同，CAS 也会失败。

### 它到底修复了什么

tagged pointer 修复的是这个漏洞：

- “我现在看到的地址还是 A”
- 并不等于
- “中间从来没人改过 head”

也就是说，它让 CAS 从“只比较地址”升级成“比较地址加历史版本”。

### 它没有自动解决什么

tagged pointer 不是万能内存回收器。即使版本号能防住 ABA，如果某个线程还会访问已释放节点，仍然需要 hazard pointer、epoch GC 或引用计数之类的回收协议来保证安全释放时机。

## 为什么 SPSC 队列不需要专门处理 ABA

SPSC 的关键性质是：

- `head_` 只有消费者写
- `tail_` 只有生产者写

这意味着：

1. 不存在多个线程同时 CAS 同一个栈顶指针
2. 环形数组槽位复用依赖索引推进，不依赖“抢同一个节点指针”
3. 生产者和消费者不会围绕同一个原子指针反复做比较交换

因此，SPSC 的共享状态是“单写多读的索引”，而不是“多线程竞争修改的链表头指针”。ABA 问题发生的土壤本来就不存在。

## 今天的收获

1. ABA 本质是 CAS 只看瞬时值、不看中间历史。
2. tagged pointer 给 CAS 补上了“历史版本”这层信息。
3. SPSC 的正确性优势，不只在于快，也在于状态机简单、冲突面小。

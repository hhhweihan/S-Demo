## 今日目标

昨天的 `unique_ptr` 解决的是“一个资源只能有一个拥有者”。

今天的 `shared_ptr` 要解决的是另一个问题：

> 如果一块资源确实需要被多个对象共同持有，应该由谁来决定什么时候释放？

答案不是让某一个指针“猜”，而是把“还有多少拥有者”这件事单独记录下来。这就是控制块存在的原因。

今天要吃透四件事：

1. **对象本身和计数信息要分开存。**
2. **拷贝不是复制资源，而是共享控制权。**
3. **最后一个 `shared_ptr` 离开时才销毁对象。**
4. **控制块和对象不是一回事。对象销毁后，控制块也不一定立刻销毁。**

第四点会在明天 `weak_ptr` 时真正显现出来，所以今天先把模型搭牢。

---

## 为什么 `shared_ptr` 不能只靠一个裸指针

如果你写出下面这种代码：

```cpp
SharedPtr<int> a(new int(42));
SharedPtr<int> b = a;
SharedPtr<int> c = b;
```

那么 `a`、`b`、`c` 都指向同一个对象。问题是：

- `a` 析构时能不能删？不能，因为 `b`、`c` 还在用
- `b` 析构时能不能删？也不能
- 只有最后一个析构的人才有资格删

所以必须有一个共享的“记账员”记录当前还有多少个 `SharedPtr` 在持有对象，这个记账员就是 **控制块（control block）**。

---

## 控制块设计

教学版可以先这样设计：

```cpp
struct ControlBlockBase {
  std::atomic<int> use_count{1};
  std::atomic<int> weak_count{0};

  virtual void destroy_object() = 0;
  virtual void* get_object_ptr() = 0;
  virtual ~ControlBlockBase() = default;
};

template<typename T>
struct ControlBlockPtr : ControlBlockBase {
  T* ptr;

  explicit ControlBlockPtr(T* p) : ptr(p) {}

  void destroy_object() override {
    delete ptr;
    ptr = nullptr;
  }

  void* get_object_ptr() override {
    return ptr;
  }
};
```

这里先保留 `weak_count`，即使今天还没正式实现 `WeakPtr`。原因很简单：

1. `shared_ptr` 的完整模型离不开控制块生命周期
2. 明天实现 `weak_ptr` 时可以直接接上，不用再推翻今天的设计

### 这几个成员分别负责什么

- `use_count`：当前有多少个 `SharedPtr` 正在共享对象
- `weak_count`：当前有多少个 `WeakPtr` 观察这个控制块
- `destroy_object()`：负责真正销毁托管对象
- `get_object_ptr()`：返回底层对象地址，供 `SharedPtr<T>` 取回 `T*`

## `SharedPtr<T>` 的最小结构

和昨天只存一个 `T*` 不一样，今天至少要存两个指针：

```cpp
template<typename T>
class SharedPtr {
  T* ptr_ = nullptr;
  ControlBlockBase* control_ = nullptr;
};
```

- `ptr_` 负责像普通指针一样访问对象
- `control_` 负责连接到共享控制块，修改引用计数

很多人第一次学这里会问：既然控制块里已经能拿到对象，为什么 `SharedPtr` 自己还要再存一个 `ptr_`？

原因是接口访问会更直接，后面做继承层次和别名构造时也更方便。教学版先把“对象指针”和“控制块指针”分开理解，思路最清楚。

## 参考实现

下面这个版本覆盖今天需要理解的关键行为：

```cpp
#include <atomic>
#include <utility>

struct ControlBlockBase {
  std::atomic<int> use_count{1};
  std::atomic<int> weak_count{0};

  virtual void destroy_object() = 0;
  virtual void* get_object_ptr() = 0;
  virtual ~ControlBlockBase() = default;
};

template<typename T>
struct ControlBlockPtr : ControlBlockBase {
  T* ptr;

  explicit ControlBlockPtr(T* p) : ptr(p) {}

  void destroy_object() override {
    delete ptr;
    ptr = nullptr;
  }

  void* get_object_ptr() override {
    return ptr;
  }
};

template<typename T>
class SharedPtr {
  T* ptr_ = nullptr;
  ControlBlockBase* control_ = nullptr;

  void release_current() {
    if (!control_) {
      return;
    }

    if (--control_->use_count == 0) {
      control_->destroy_object();
      if (control_->weak_count == 0) {
        delete control_;
      }
    }

    ptr_ = nullptr;
    control_ = nullptr;
  }

public:
  SharedPtr() noexcept = default;

  explicit SharedPtr(T* p) : ptr_(p) {
    if (p) {
      control_ = new ControlBlockPtr<T>(p);
    }
  }

  ~SharedPtr() {
    release_current();
  }

  SharedPtr(const SharedPtr& other) noexcept
    : ptr_(other.ptr_), control_(other.control_) {
    if (control_) {
      ++control_->use_count;
    }
  }

  SharedPtr& operator=(const SharedPtr& other) noexcept {
    if (this != &other) {
      release_current();
      ptr_ = other.ptr_;
      control_ = other.control_;
      if (control_) {
        ++control_->use_count;
      }
    }
    return *this;
  }

  SharedPtr(SharedPtr&& other) noexcept
    : ptr_(other.ptr_), control_(other.control_) {
    other.ptr_ = nullptr;
    other.control_ = nullptr;
  }

  SharedPtr& operator=(SharedPtr&& other) noexcept {
    if (this != &other) {
      release_current();
      ptr_ = other.ptr_;
      control_ = other.control_;
      other.ptr_ = nullptr;
      other.control_ = nullptr;
    }
    return *this;
  }

  T* get() const noexcept {
    return ptr_;
  }

  T& operator*() const {
    return *ptr_;
  }

  T* operator->() const noexcept {
    return ptr_;
  }

  int use_count() const noexcept {
    return control_ ? control_->use_count.load() : 0;
  }

  explicit operator bool() const noexcept {
    return ptr_ != nullptr;
  }
};
```

## 关键语义拆解

### 1. 构造时为什么要新建控制块

```cpp
explicit SharedPtr(T* p) : ptr_(p) {
  if (p) {
    control_ = new ControlBlockPtr<T>(p);
  }
}
```

和 `unique_ptr` 不同，`shared_ptr` 不能只拿到对象地址就结束了。因为以后任何一个副本都需要知道“还有几个人在持有这个对象”。

所以第一位拥有者创建对象时，就必须顺手创建控制块。

### 2. 拷贝构造为什么要加计数

```cpp
SharedPtr(const SharedPtr& other) noexcept
  : ptr_(other.ptr_), control_(other.control_) {
  if (control_) {
    ++control_->use_count;
  }
}
```

这里不是复制对象，而是复制“指向同一对象的共享所有权”。

所以每发生一次拷贝，`use_count` 都要加一。

### 3. 移动构造为什么不加计数

```cpp
SharedPtr(SharedPtr&& other) noexcept
  : ptr_(other.ptr_), control_(other.control_) {
  other.ptr_ = nullptr;
  other.control_ = nullptr;
}
```

移动不是新增一个拥有者，而是把原来的拥有者身份换个壳继续存在，所以计数不变。

这个点和昨天的 `unique_ptr` 是一致的：**move 转移所有权，不复制所有权。**

### 4. 析构时到底销毁什么

```cpp
if (--control_->use_count == 0) {
  control_->destroy_object();
  if (control_->weak_count == 0) {
    delete control_;
  }
}
```

这段要分两层理解：

1. `use_count == 0`：说明没有 `SharedPtr` 再拥有对象了，所以对象本身可以销毁
2. `weak_count == 0`：说明连观察者也没有了，这时控制块本身才可以销毁

今天虽然还没有 `WeakPtr`，但这个两阶段模型必须先建立起来。

## 建议测试代码

下面这段代码足够验证今天最关键的行为：

```cpp
#include <iostream>

struct Test {
  int value;

  explicit Test(int v) : value(v) {
    std::cout << "Test(" << value << ") ctor\n";
  }

  ~Test() {
    std::cout << "Test(" << value << ") dtor\n";
  }

  void hello() const {
    std::cout << "hello: " << value << "\n";
  }
};

int main() {
  SharedPtr<Test> p1(new Test(100));
  std::cout << "p1 count = " << p1.use_count() << "\n";

  {
    SharedPtr<Test> p2 = p1;
    std::cout << "after p2 copy, count = " << p1.use_count() << "\n";

    {
      SharedPtr<Test> p3 = p2;
      std::cout << "after p3 copy, count = " << p1.use_count() << "\n";
      p3->hello();
    }

    std::cout << "after p3 destroyed, count = " << p1.use_count() << "\n";
  }

  std::cout << "after p2 destroyed, count = " << p1.use_count() << "\n";

  return 0;
}
```

### 预期现象

1. 创建 `p1` 后，计数是 1
2. 拷贝出 `p2` 后，计数变成 2
3. 再拷贝出 `p3` 后，计数变成 3
4. `p3` 离开作用域后，计数回到 2，对象不析构
5. `p2` 离开作用域后，计数回到 1，对象仍不析构
6. 最后 `p1` 离开作用域，计数归零，对象析构一次且只析构一次

## 今天最容易写错的地方

### 1. 拷贝时忘记增加 `use_count`

这会导致多个 `SharedPtr` 共同指向一个对象，但计数仍然偏小，最终过早释放对象。

### 2. 移动时错误地增加计数

move 不应该制造新的拥有者。如果移动构造里也做 `++use_count`，计数会虚高，最终导致对象无法按时释放。

### 3. 析构时只删对象，不处理控制块

哪怕对象已经删了，控制块仍可能被 `weak_ptr` 持有。今天先记住这个两阶段模型，明天就不会乱。

### 4. 赋值运算符里没有先释放当前对象

例如当前 `this` 已经持有一块资源，又直接接管 `other`，那么旧资源对应的计数就永远少减一次，形成泄漏。

### 5. 空指针场景没处理

默认构造出的空 `SharedPtr` 应该是合法状态：

```cpp
SharedPtr<int> p;
```

这时 `use_count()` 应该返回 0，而不是访问空控制块崩溃。

## 和标准库 `std::shared_ptr` 的差距

今天这个版本是教学版，和标准库还差不少：

1. **线程安全细节不完整。** 标准库对多线程并发拷贝、析构和内存序有更严谨的保证。
2. **没有 `make_shared`。** 标准库通常会把控制块和对象一次性分配，减少一次堆分配并改善缓存局部性。
3. **没有自定义删除器。** 实际工程里共享的不一定是 `new/delete` 分配出的对象。
4. **没有别名构造、类型转换构造等高级接口。**
5. **还没接上 `WeakPtr`。** 所以当前只能理解完整模型的一半。

但只要今天这版写清楚，你已经掌握了 `shared_ptr` 最本质的东西：

> `shared_ptr` 的核心不是“多个指针指向同一个对象”，而是“多个句柄共享同一个控制块”。

## 今天和昨天的本质差异

可以把 `unique_ptr` 和 `shared_ptr` 并排记：

| 项目 | `unique_ptr` | `shared_ptr` |
|------|--------------|--------------|
| 所有权模型 | 独占 | 共享 |
| 是否允许拷贝 | 不允许 | 允许 |
| 是否需要控制块 | 不需要 | 需要 |
| 资源何时释放 | 拥有者析构时 | 最后一个拥有者析构时 |
| 实现重点 | move 语义 | 引用计数 + 控制块 |

这个对比如果脑子里不清楚，后面写 `weak_ptr` 会很容易把“观察者”和“拥有者”混成一类。

## 今日总结（完成后填写）

1. `SharedPtr<T>` 至少要同时管理两样东西：对象指针和控制块指针。
2. 拷贝意味着新增一个共享拥有者，所以 `use_count` 加一；移动只是转移句柄，不增加计数。
3. 对象销毁和控制块销毁是两阶段：`use_count == 0` 先销毁对象；若 `weak_count == 0`，再销毁控制块。
4. `shared_ptr` 真正共享的不是“裸指针变量”，而是“同一个控制块中的生命周期管理权”。

**明天衔接：** 明天的 `weak_ptr` 会解释为什么对象已经析构后，控制块还要继续活着。今天只要把“控制块比对象活得更久”这件事想通，Day 17 就会顺很多。

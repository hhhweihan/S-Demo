## Day 12（Fri）— 线程安全 + 性能测试

**预计时间：1 小时**

**任务：**
- [x] 给每个 FixedAllocator 加 `std::mutex`，`allocate/deallocate` 加锁
- [x] 测试多线程安全：4 个线程各分配/释放 10 万次，验证无崩溃
- [x] Benchmark 对比（分配/释放 100 万次，32 字节对象）：
  ```
  new/delete
  PoolAllocator（单线程）
  PoolAllocator（加锁，4 线程竞争）
  ```
- [x] 把结果写到「本周结果」

**完成标志：** 多线程无崩溃，单线程 PoolAllocator 比 new 快 2x+

**实现说明：**
- 在 `FixedAllocator` 内部加入 `std::mutex`，并对 `init`、`allocate`、`deallocate`、`stats` 做互斥保护；锁粒度保持在单个 size class，对 `PoolAllocator` 层不额外加全局锁。
- 新增 4 线程并发测试：共享一个 `PoolAllocator`，每个线程执行 10 万次 `32` 字节对象的分配与释放，结束后验证对应 class 的 `used == 0`。
- 新增 Day-012 benchmark：对比 `new/delete`、`PoolAllocator` 单线程、`PoolAllocator` 4 线程竞争三种路径。
- benchmark 的实际数值已回填到本周结果页。

**当前结果：**
- 正确性目标已完成：4 线程并发分配/释放测试通过，程序无崩溃，池内统计能回到 `0`。
- 性能数据以 Release 构建为准：`new/delete = 25.890 ms`，`PoolAllocator 单线程 = 19.597 ms`，`PoolAllocator 4 线程竞争 = 56.018 ms`。
- 当前单线程版本相对 `new/delete` 约为 `1.321x`，还没有达到“2x+”这个激进目标；主要额外成本来自互斥锁、header 元数据和通用 size class 路由。

## Day 9（Tue）— 实现 PoolAllocator 核心

**预计时间：1 小时**

**任务：**
- [x] `PoolAllocator` 内部持有 16 个 `FixedAllocator` 数组
- [x] 构造时初始化每个 FixedAllocator（block_size 对应 size class 大小，初始 64 块）
- [x] `allocate(n)`：调用 `size_to_class(n)` 路由，返回对应 FixedAllocator 的块
- [x] `deallocate(ptr, n)`：同样路由回对应的 FixedAllocator 释放
- [x] 测试：分配 20 字节 10 次，分配 200 字节 10 次，stats 显示两个 class 各用了 10 块

**完成标志：** 多 size class 分配/释放正常，stats 数字正确

**实现说明：**
- 前 15 个 `FixedAllocator` 分别对应 `8..1024` 这 15 个小对象档位。
- 第 16 个 slot 先预留给 `>1024` 的大对象路径，便于 Day-10 接入 header 标记逻辑；当前版本的大对象暂时直接走 `malloc/free`。
- 增加了 `stats_for_class` / `stats_for_size`，便于验证不同 size class 的占用情况。

**测试结果：**
- `20` 字节请求被路由到 `24` 字节 class，连续分配 `10` 次后该 class 的 `used == 10`
- `200` 字节请求被路由到 `256` 字节 class，连续分配 `10` 次后该 class 的 `used == 10`
- 回收后两个 class 的 `used` 都回到 `0`

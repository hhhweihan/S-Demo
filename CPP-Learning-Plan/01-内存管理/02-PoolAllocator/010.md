## Day 10（Wed）— 大对象 fallback + header 标记

**预计时间：1 小时**

**任务：**
- [x] 大对象（>1024）直接走 `malloc`，但要记录这是大对象（在指针前加 8 字节 header）
  ```cpp
  struct Header { bool is_large; size_t size; };
  void* p = malloc(sizeof(Header) + n);
  new(p) Header{true, n};
  return (char*)p + sizeof(Header);
  ```
- [x] `deallocate` 时回退 kUserPointerOffset（对齐后为 16 字节）读 header，判断走 pool 还是 `free`
- [x] 同样给 pool 分配的块加 header（记录 class index），这样 `deallocate` 不再需要传 size
  ```cpp
  void deallocate(void* ptr);  // 不需要 size 参数！
  ```
- [x] 更新 `allocate/deallocate` 接口，测试混合大小分配/释放不崩溃

**完成标志：** `deallocate` 只需要 `ptr` 一个参数，大小对象混合分配正常

**实现说明：**
- 实际实现里使用一个 `size_t` 作为统一 header，占用 8 字节；最高位作为 `large` 标记，其余位存储大对象大小或小对象的 class index。
- 小对象分配时，`FixedAllocator` 管理的真实块大小变成 `header + 对齐 padding + payload`（整体向上取整到 max_align_t），返回给用户的是跳过 header 后的地址。
- 大对象分配时，直接 `malloc(header + n)`，释放时只需回退 kUserPointerOffset（对齐后为 16 字节）读取 header，即可判断是回池还是 `free`。
- 因为 header 已经携带元信息，`deallocate` 接口已改为只接收 `ptr`。

**测试结果：**
- 保留 Day-009 的 20 字节 / 200 字节 stats 验证，并改成 `deallocate(ptr)` 释放
- 新增混合分配测试：`20 / 200 / 1024 / 1025 / 4096` 字节对象混合分配后统一释放，过程不崩溃
- 小对象 class 的 `used` 计数在释放后能够回到 `0`

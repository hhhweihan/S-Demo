## 如果这些问题真的出现，根因通常会是什么

虽然本轮没复现报错，但下面三类问题仍然是 Month 1 最需要警惕的：

### 1. `heap-use-after-free`

典型根因：

- `SharedPtr` 引用计数少减或多减，导致对象提前析构后继续访问
- `FixedAllocator` 把非法指针塞回 free list，后续重新分配出脏地址
- 移动语义后源对象未置空，析构重复释放后又继续访问

当前代码里对应的防线：

- `UniquePtr` 和 `FileGuard` 的 move 后源对象都显式置空
- `SharedPtr` 的释放逻辑集中在 `release_current()`
- `FixedAllocator` 在 Debug 下对回收指针做范围与对齐断言

### 2. `heap-buffer-overflow`

典型根因：

- block size 计算错误
- 用户指针对齐偏移错误
- header 写入区域和真实 payload 重叠

当前代码里对应的防线：

- `PoolAllocator` 使用 `kUserPointerOffset` 保证 header 之后的用户指针按 `max_align_t` 对齐
- 小对象档位和大对象 fallback 路径拆开处理
- `class_to_block_size()` 和 `size_to_class()` 在测试里做了系统校验

### 3. `memory leak`

典型根因：

- 控制块没有在最后一次释放后销毁
- 大对象 fallback 路径只分配不回收
- 线程本地缓存没有在合适时机 flush

当前代码里对应的防线：

- `PoolAllocator` 对大对象走 `malloc/free` 的对称路径
- TLS cache 提供 `flush_current_thread_cache()`
- `ScopeGuard`、`DEFER`、`FileGuard` 让异常路径也能走释放逻辑

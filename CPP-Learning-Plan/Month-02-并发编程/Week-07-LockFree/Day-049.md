## 本周结果

### 6 种 memory_order 一句话定义

| memory_order | 含义 |
|-------------|------|
| relaxed | 只保证当前原子操作本身不可撕裂，不提供跨线程顺序语义 |
| consume | 只保证依赖链上的后续读可见，实践里通常按 acquire 理解 |
| acquire | 这次读之后的操作不能重排到它之前，常用于“观察到别人发布的数据” |
| release | 这次写之前的操作不能重排到它之后，常用于“把数据发布出去” |
| acq_rel | 用于读改写原子操作，同时承担 acquire 和 release 语义 |
| seq_cst | 在 acquire/release 基础上增加全局一致的单一总顺序，最强也最保守 |

### 用锁还是无锁：判断矩阵

| 维度 | 更适合用锁 | 更适合无锁 |
|------|------------|------------|
| 并发模型 | 多生产者多消费者、共享状态复杂 | 单生产者单消费者、状态转换清晰 |
| 正确性压力 | 更看重可维护性与排障成本 | 团队能严格证明内存模型与回收策略 |
| 延迟目标 | 微秒级不是核心诉求 | 对尾延迟和吞吐很敏感 |
| 数据结构复杂度 | 涉及复杂节点生命周期或多步事务 | 状态少、可拆成原子索引或单步 CAS |
| 团队经验 | 大家更熟悉互斥锁与条件变量 | 团队能稳定处理 ABA、回收、缓存抖动 |

结论很直接：能用锁先用锁，只有在热点路径被锁成本明确卡住、并且问题规模足够受控时，才值得上无锁。

### SPSC vs 有锁队列性能结论

本周没有在仓库中落地新的 benchmark 代码，因此这里记录的是结论口径，而不是本机实测数据：

| 方案 | 结论 |
|------|------|
| SPSCQueue | 在单生产者单消费者场景下，通常是三者里同步成本最低的一档 |
| BlockingQueue | 语义最直观，但会引入锁竞争与条件变量唤醒开销 |
| BoundedQueue | 如果实现仍依赖锁与条件变量，性能通常介于 SPSC 和通用阻塞队列之间 |

### SPSC 更快的原因

1. 只维护两个单写者索引，冲突面很小。
2. 热路径主要是数组读写和少量原子操作，没有互斥锁与条件变量切换。
3. 环形缓冲区局部性更好，避免了链式节点和频繁动态分配的额外成本。

### 本周真正吃透的点

1. 原子性不等于同步语义，memory_order 才决定线程间可见性规则。
2. ABA 不是值比较失误，而是中间历史被“地址复原”掩盖。
3. 无锁数据结构的难点经常不在 CAS，而在内存回收。
4. SPSC 是最适合入门无锁编程的形态，因为约束强、证明成本低。

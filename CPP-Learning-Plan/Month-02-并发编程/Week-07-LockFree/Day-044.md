## 核心理解

### 1. 无锁栈本体其实很小，难点全在边界条件

栈顶指针是一个原子量，push/pop 的骨架非常简洁：

```cpp
template<typename T>
class LockFreeStack {
    struct Node { T data; Node* next; };
    std::atomic<Node*> head_{nullptr};
public:
    void push(T value) {
        Node* node = new Node{std::move(value), head_.load(std::memory_order_relaxed)};
        while (!head_.compare_exchange_weak(node->next,
                                            node,
                                            std::memory_order_release,
                                            std::memory_order_relaxed)) {}
    }

    bool pop(T& out) {
        Node* old = head_.load(std::memory_order_acquire);
        while (old && !head_.compare_exchange_weak(old,
                                                   old->next,
                                                   std::memory_order_acquire,
                                                   std::memory_order_relaxed)) {}
        if (!old) {
            return false;
        }
        out = old->data;
        delete old;
        return true;
    }
};
```

表面上看已经“无锁”，但这只是把互斥锁换成了 CAS。真正的难点是：当你把 `head_` 改掉后，原先看到的那个节点是否仍然有效。

### 2. ABA 不是“值相同”这么简单，而是“历史被掩盖”

手工构造一个典型过程：

1. 线程 T1 读到 `head = A`，准备把它 CAS 成 `B`
2. 线程 T2 抢先把 `A` 弹出，又把 `B` 弹出
3. 线程 T2 再把 `A` 压回去，此时栈顶又回到 `A`
4. 线程 T1 醒来后发现 `head` 还是 `A`，CAS 居然成功

问题在于：

- T1 以为自己看到的是“原来的 A”
- 但实际上中间栈结构已经变过一次甚至多次
- 如果 `A` 对应内存已经释放或复用，T1 手里的指针就可能悬空

所以 ABA 的本质不是 CAS 判等错了，而是“地址恢复原样”掩盖了中间历史。

### 3. 为什么 `delete old` 危险

`pop()` 一旦 CAS 成功就立刻 `delete old`，在单线程里没问题，在并发场景里却可能导致两类风险：

- 另一个线程还持有 `old` 的快照，随后访问成为 use-after-free
- 被释放的地址很快被新节点复用，CAS 看起来仍然“匹配”，从而引发 ABA

这说明无锁结构的正确性分成两层：

1. 逻辑结构更新是否原子
2. 旧内存何时允许回收

第一层靠 CAS，第二层必须靠额外方案，例如 tagged pointer、hazard pointer、epoch reclamation 或 `shared_ptr` 风格延迟释放。

## 今天的收获

1. `compare_exchange_weak` 循环只是入口，不是终点。
2. 无锁栈真正难的是内存回收，不是栈接口本身。
3. 看到“地址没变”不能说明“对象还是原来那个对象”。

## 你需要掌握的点

### 1. MPMC 到底是什么意思

MPMC 是：

- Multiple Producer
- Multiple Consumer

也就是：

- 多个生产者线程同时入队
- 多个消费者线程同时出队

注意，这里的重点不是“多线程”三个字，而是：

- 多方都能并发访问同一个队列，而且尽量不依赖全局互斥锁

你这周写的 `BlockingQueue` 也可以服务多个生产者和多个消费者，但它的核心同步手段是：

- 一把 mutex
- 一个或两个 condition_variable

而 `MPMCQueue` 的思路是尽量通过原子操作和槽位状态管理来完成并发协调。

### 2. 它和你的 BlockingQueue 的本质区别是什么

不要把区别理解成“一个高级，一个初级”。真正的本质区别是同步模型不同：

- `BlockingQueue`：通过锁把共享状态串行化，再用条件变量解决等待
- `MPMCQueue`：尽量不把所有访问串到一把全局锁上，而是依靠原子变量、序号或槽位状态进行细粒度协调

换句话说：

- 你的队列是“先互斥，再操作”
- folly 这类队列更接近“通过原子协议判断自己能否占有某个位置”

### 3. folly 主要用什么机制替代 mutex

今天你不需要追具体每一行实现，但应该看懂大方向：

- 原子变量
- CAS（compare-and-swap）或类似原子读改写
- 每个槽位的状态/序号管理

这套机制的核心目的，是在不使用全局锁的前提下，让多个线程仍然能安全地：

- 竞争写入位置
- 竞争读取位置
- 判断某个槽位当前是否可用

### 4. 为什么 MPMC 比 SPSC 难很多

SPSC 只有：

- 一个生产者
- 一个消费者

因此很多竞争关系天然不存在：

- 写指针只有一个线程改
- 读指针只有一个线程改
- 不需要多个生产者抢同一个写位置
- 不需要多个消费者抢同一个读位置

一旦到 MPMC，复杂度会明显上升，因为你需要同时处理：

- 多个生产者之间的竞争
- 多个消费者之间的竞争
- 生产者和消费者之间的可见性顺序
- 槽位复用时的 ABA / 轮次 / 序号问题

所以 MPMC 难的不是“代码更长”，而是正确性状态空间暴涨。

### 第一步：只看类注释，不看实现细节

今天不要一上来钻到模板细节、内存序和辅助类里，否则很容易读崩。

不要试图一次读懂所有 corner case。

## 你应该得到的高层结论

读完今天的内容后，你至少应该能说清楚这几点：

1. `BlockingQueue` 的主要优势是实现简单、阻塞语义清晰。
2. MPMCQueue 的主要优势是减少全局锁竞争，追求更高并发吞吐。
3. 复杂度差异不是编码技巧问题，而是并发模型本身更难。
4. 工业级无锁结构往往需要更严格的内存序、状态机和测试保障。

## 常见坑

### 1. 一上来就啃实现细节

如果你还没有建立清晰问题框架，直接读实现通常只会看到大量模板和原子操作，收获很少。

### 2. 把“无锁”误解成“没有等待”

无锁不等于零成本，也不等于所有线程都不会卡。

它通常只是表示：

- 不依赖传统互斥锁来保证整体推进

具体接口仍然可能有重试、自旋、等待策略等成本。

### 3. 试图一口气理解完整正确性证明

今天你的目标只是建立比较框架，不是重写 folly。

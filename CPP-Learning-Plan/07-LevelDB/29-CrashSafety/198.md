## 编号 198 — 块式 SSTable：data block + 持久 bloom + index + footer

**掌握标准：能画出 SSTable 文件布局、说清「读一个 key 走哪几步」，并解释 restart 点为什么让前缀
压缩仍可随机定位。**

### 文件布局

```
[data block 0]      前缀压缩 + restart 二分
[data block 1]
...
[bloom block]       BloomFilter::Encode()（持久化，可配 bits_per_key）
[index block]       每个 data block 的「最后一个 key → BlockHandle(offset,size)」
[footer]            定长 48B：bloom handle(16) + index handle(16) + num_entries(8) + magic(8)
```

读一个 key：`footer` → 载入 bloom（`MayContain` 快速否定）→ 二分 index 定位候选块 → 只解析那一个块。

### data block 内格式（`lsm/block.h`）

每条 entry：`shared(4) | non_shared(4) | value_len(4) | key_delta | value`。

- **前缀压缩**：只存与前一条 key 的增量（相邻 key 常有长公共前缀）。
- **restart 点**：每隔 `kBlockRestartInterval=16` 条强制存整 key（`shared=0`）并记录偏移；块尾是
  `restart[0..R-1](各4) | num_restarts(4)`。查找时先在 restart 点（都是完整 key）上二分锁定区间，再从
  最近的 restart 点线性解码一小段——把「必须从头解码」降到「解码一段」。

value 编码为 `[type:1][value]`，把 `kValue/kDeletion` 一并持久化（删除信息要落盘才能跨层遮蔽）。

### 健壮性（ASan 风险点）

块/footer 解析全程做边界检查：footer 的 handle 越界、restart 偏移越界、entry 长度越界、`shared >
prev.size()` 都返回失败而非越界读。`magic` 不符或文件短于 footer 即判 invalid（截断/半写文件安全跳过）。

### 落盘 durability

`BuildFromEntries` 累积整个文件字节后 `O_TRUNC` 写入并 `fsync`（macOS `F_FULLFSYNC`）。半写的 .sst
因 footer magic 缺失被 `Load` 判 invalid，其数据仍在未轮转的 WAL 中可被重放恢复。

### 验证

- `Block.RoundTripWithPrefixCompressionAndBinarySearch`：100 个带公共前缀 key 全部命中，越界/不精确
  匹配返回空。
- 既有 `SSTableBuildThenGet` / `SSTableFileRoundTrip`：API 不变，透明切到二进制块式格式仍全绿。

## Day 78（Mon）— CRTP 静态多态

**预计时间：1 小时**

**任务：**
- [x] 理解 CRTP（Curiously Recurring Template Pattern）：
  ```cpp
  template<typename Derived>
  class Shape {
  public:
      double area() const {
          return static_cast<const Derived*>(this)->area_impl();
      }
      void print() const { std::cout << "Area: " << area(); }
  };
  class Circle : public Shape<Circle> {
      double r_;
  public:
      double area_impl() const { return 3.14 * r_ * r_; }
  };
  ```
- [x] 对比：CRTP（静态多态）vs 虚函数（动态多态）的性能差异
- [x] 用 benchmark 测量：1000 万次 area() 调用，CRTP vs virtual，各自耗时

**完成标志：** CRTP 版本比 virtual 快（因为无 vtable 查找），有数据支撑

## 实践落点

- 代码目录：`CPP-Practice/advanced_templates/`
- 入口文件：`CPP-Practice/advanced_templates/main.cpp`
- 验证函数：`run_crtp_benchmark()`

## 实测数据

- CRTP area loop：约 `6.517 ms`
- virtual area loop：约 `12.798 ms`

## 本日结论

- CRTP 把多态分发提前到编译期，适合类型集合已知、追求内联和零虚调用成本的场景
- 虚函数适合运行时多态和 ABI 稳定边界，但每次调用需要经过 vtable 间接分发
- benchmark 只能说明当前实现和当前编译器下的结果，真实项目仍要结合可维护性选择

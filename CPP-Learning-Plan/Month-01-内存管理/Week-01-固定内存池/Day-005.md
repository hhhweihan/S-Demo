## Day 5（Fri）— Benchmark 对比

**预计时间：1 小时**

**任务：**
- [x] 分别测量以下三种方式分配/释放 **100 万次** 的总耗时：
  ```cpp
  // 方案 A：new/delete
  int* p = new int; *p = 42; delete p;

  // 方案 B：FixedAllocator
  void* p = alloc.allocate(); *(int*)p = 42; alloc.deallocate(p);

  // 方案 C：malloc/free
  int* p = (int*)malloc(sizeof(int)); *p = 42; free(p);
  ```
- [x] 用 `std::chrono::high_resolution_clock` 计时
- [x] 把结果记录在本文件底部的「本周结果」区域
- [x] 分析：为什么内存池更快？（省去了 malloc 内部的 mutex 和碎片处理）

**完成标志：** FixedAllocator 至少比 new 快 2x

---

## 本周结果

**测试环境：** Windows + MSVC Release（Ninja），迭代次数 `1,000,000`

**原始输出：**

```text
Day 005 benchmark (1000000 iterations)
  new/delete: 22.077 ms
  FixedAllocator: 2.200 ms
  malloc/free: 23.373 ms
  FixedAllocator speedup vs new/delete: 10.034x
  FixedAllocator speedup vs malloc/free: 10.623x
```

**结论：**

- `FixedAllocator` 相比 `new/delete` 提升约 `10.03x`，满足“至少 2x”的目标。
- `FixedAllocator` 相比 `malloc/free` 提升约 `10.62x`。

**原因分析：**

- 固定内存池走 O(1) 的 free list 头部弹出/插回，路径极短。
- 预分配 chunk 后，热路径不需要反复进入通用分配器。
- 通用分配器（`new/delete`、`malloc/free`）需要处理更复杂的元数据管理、潜在碎片与并发同步逻辑，单次开销更高。

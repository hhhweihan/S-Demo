## 读源码笔记

**阅读文件位置（本地）：**

- `TestProject/nginx/src/core/ngx_palloc.h`
- `TestProject/nginx/src/core/ngx_palloc.c`

1. nginx 如何区分「小块」和「大块」分配？阈值是多少？

- 入口在 `ngx_palloc()` / `ngx_pnalloc()`：
  - `size <= pool->max` 走小块分配（`ngx_palloc_small`）
  - `size > pool->max` 走大块分配（`ngx_palloc_large`）
- `pool->max` 在 `ngx_create_pool()` 里设置为：
  - `min(size - sizeof(ngx_pool_t), NGX_MAX_ALLOC_FROM_POOL)`
- `NGX_MAX_ALLOC_FROM_POOL` 定义是 `(ngx_pagesize - 1)`，典型 x86 上是 `4095`。
- 因此实际阈值是“池可用空间”和“页大小减 1”两者较小值，不是固定写死常量。

2. `ngx_pool_t` 结构体里 `d.last`、`d.end`、`d.next` 分别是什么？

- `d.last`：当前这个 pool block 的“已分配区域尾指针”（下一次小块分配起点）。
- `d.end`：当前这个 pool block 的末尾地址（边界上限）。
- `d.next`：下一个 pool block 指针，用于把多个 block 串成链表（空间不够时扩展新 block）。

3. nginx 的内存池为什么不支持释放单个 block（只能整池销毁）？

- 小块分配是 bump-pointer 线性推进（移动 `d.last`），不维护每个小对象的独立元数据与回收链。
- 这种设计让分配路径极短、局部性好、开销低，但代价是无法对小块做精细回收。
- 释放策略改为“按生命周期批量释放”：
  - 要么 `ngx_reset_pool()` 重置池
  - 要么 `ngx_destroy_pool()` 整池销毁
- 只有“大块分配”（`pool->large` 链）支持 `ngx_pfree()` 按块 free。

4. 我的 FixedAllocator 和 nginx 内存池的核心设计差异是什么？

- 分配模型不同：
  - 我的 `FixedAllocator`：固定块大小 + free list，可 O(1) 分配，也可 O(1) 回收单块。
  - nginx pool：小块线性切分 + 大块单独管理，偏向“快速申请，批量释放”。
- 适用场景不同：
  - `FixedAllocator` 更适合大量同尺寸对象、频繁申请/释放。
  - nginx pool 更适合请求级/阶段性内存，生命周期集中结束。
- 碎片与管理开销取舍不同：
  - `FixedAllocator` 通过固定尺寸避免外部碎片，但可能有内部碎片。
  - nginx 小块池几乎无单对象管理开销，不追求小块单独释放能力。

**结论：**

- nginx 内存池的核心目标是“请求生命周期内的高吞吐分配 + 生命周期末端一次性回收”。
- 我的 `FixedAllocator` 目标是“固定尺寸对象的高频复用与可回收单块”。
- 两者都是“用约束换性能”，但约束方向不同。

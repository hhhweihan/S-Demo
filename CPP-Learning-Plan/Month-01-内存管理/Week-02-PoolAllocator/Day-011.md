## Day 11（Thu）— 适配 std::allocator 接口

**预计时间：1 小时**

**任务：**
- [x] 写 `MyAllocator<T>` 类，满足 C++ allocator 要求：
  ```cpp
  template<typename T>
  class MyAllocator {
  public:
      using value_type = T;
      T* allocate(std::size_t n);    // 分配 n 个 T
      void deallocate(T* p, std::size_t n);
      // rebind 等必要接口
  };
  ```
- [x] `MyAllocator` 内部用单例 `PoolAllocator`（或传入引用）
- [x] 测试：
  ```cpp
  std::vector<int, MyAllocator<int>> v;
  for (int i = 0; i < 10000; i++) v.push_back(i);
  assert(v[9999] == 9999);
  ```

**完成标志：** `std::vector<int, MyAllocator<int>>` 能正常 push_back/读取

**实现说明：**
- 新增 `my_allocator.h`，提供 `MyAllocator<T>` 模板，包含 `value_type`、`rebind`、`max_size`、跨类型拷贝构造和相等性语义，满足 `allocator_traits` 的基本要求。
- `MyAllocator<T>` 内部通过 `global_pool_allocator()` 使用单例 `PoolAllocator`。
- 为了让 allocator 更稳妥地服务容器分配，`PoolAllocator` 的用户指针偏移从“仅 8 字节 header”调整为“8 字节元数据 + 向 `std::max_align_t` 对齐的 padding”；header 仍然保存在块起始处。
- `allocate(n)` 会按 `n * sizeof(T)` 向底层池申请连续字节，大块容量扩容时会自动落到大对象 fallback 路径。

**测试结果：**
- `std::vector<int, MyAllocator<int>>` 连续 `push_back 10000` 次正常
- 验证了 `front()`、`back()` 和若干随机位置读取
- 额外验证了拷贝构造和移动构造场景，结果正常

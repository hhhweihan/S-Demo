## 本周结果

### 1. 这一周到底学到了什么

Week 3 的主题表面上是“手写三个智能指针”，但真正学到的不是接口本身，而是一整套资源生命周期模型：

1. `unique_ptr` 解决独占所有权问题
2. `shared_ptr` 通过控制块解决共享所有权问题
3. `weak_ptr` 把“观察”从“拥有”里分离出来，解决循环引用
4. `enable_shared_from_this` 让对象内部能够安全回到自己原有的控制块
5. libc++ 对比说明：教学版模型是对的，标准库只是把它工程化
6. 线程安全复盘说明：控制块线程安全不等于对象线程安全，也不等于句柄对象本身并发写安全

如果只背接口，很容易把这周学成“语法题”；但如果抓住“控制块 + 两个计数 + 所有权和观察权分离”，这周其实是在补 C++ 生命周期管理的底层观念。

### 2. 本周主线：从所有权角度重新理解智能指针

可以把这一周抽成一张逻辑图：

```text
unique_ptr
	-> 独占所有权
	-> 只能 move，不能 copy

shared_ptr
	-> 共享所有权
	-> 依赖控制块记录 use_count

weak_ptr
	-> 不拥有，只观察
	-> 依赖 weak_count
	-> 通过 lock() 临时升级为 shared_ptr

enable_shared_from_this
	-> 对象内部保存 weak_this_
	-> shared_from_this() 返回同一控制块上的 shared_ptr
```

这条主线真正解决的问题只有一个：

> 到底谁对资源的销毁负责，以及什么时候负责。

## libc++ 对比

1. 两种控制块的区别：

`__shared_ptr_pointer` 主要用于“对象已经在外部分配好”的场景，例如 `shared_ptr<T>(new T)`、带自定义 deleter 的构造、从 `unique_ptr` 转 `shared_ptr` 等。它保存对象指针、deleter 和 allocator，由控制块负责在引用计数归零时调用 deleter 释放对象。

`__shared_ptr_emplace` 主要用于 `allocate_shared` / `make_shared` 路径。对象直接构造在控制块内部预留的存储区里，因此对象和控制块通常只需一次分配。前者是“对象在外面，控制块单独管它”，后者是“对象在控制块里面一起分配”。

2. `make_shared` 减少一次分配的原因：

`shared_ptr<T>(new T)` 一般至少需要两次分配：一次给对象本身，一次给控制块。`make_shared` 通过 `__shared_ptr_emplace` 把控制块和对象存储放进同一块内存里统一分配，所以通常只需要一次堆分配，局部性也更好。

3. deleter 处理方式：

libc++ 会把 deleter 作为控制块状态的一部分保存下来，在共享计数归零时调用 `deleter(ptr)`，而不是写死 `delete ptr`。这使得 `shared_ptr` 可以管理 `FILE*`、socket、对象池对象等非普通 `delete` 资源。当前教学版实现默认只支持 `delete` 路径，还不支持自定义 deleter。

## shared_ptr 线程安全结论

| 场景 | 安全？ | 原因 |
|------|--------|------|
| 多线程读同一 `shared_ptr` | 有条件安全 | 前提是没有线程并发修改这个同一个句柄对象；只读本身不会造成 race |
| 多线程拷贝/析构不同 `shared_ptr`（同一对象）| 安全 | 不同句柄共享同一控制块，控制块引用计数增减使用原子操作 |
| 多线程赋值同一 `shared_ptr` | 不安全 | 竞争的是同一个智能指针变量对象本身，赋值/重置不是单个原子整体，需要外部加锁 |

补一句最容易忽略的话：

> `shared_ptr` 的线程安全只覆盖控制块生命周期管理，不覆盖被管理对象自身的并发访问。

## 本周最关键的认知收获

### 1. 智能指针不是“像指针一样用的类”

它们首先是**所有权模型**，其次才是像指针一样使用的语法外壳。

### 2. 控制块才是 `shared_ptr` 的灵魂

如果没有控制块，`shared_ptr` 只是多个裸指针指向同一对象，根本谈不上可靠生命周期管理。

### 3. `weak_ptr` 不只是“辅助接口”

它实际上把“拥有者”和“观察者”分开，是整个共享所有权模型能自洽的关键补丁。

### 4. 标准库复杂，不是因为思路完全不同

而是因为它把教学版模型扩展到了工程可用：自定义 deleter、allocator、异常安全、`make_shared` 单次分配、`enable_shared_from_this` 接入、更多边界情况。

---

## 本周最容易混淆的几个点

1. `get()` 不转移所有权，`release()` 才转移所有权。
2. `shared_ptr` 拷贝增加的是共享拥有者数量，不是复制对象。
3. `weak_ptr` 能看到对象，但不能保证对象活着，所以必须通过 `lock()` 再拿一次临时共享所有权。
4. `shared_from_this()` 不是重新包装 `this`，而是回到原控制块。
5. 引用计数线程安全，不等于同一个 `shared_ptr` 变量并发写安全。

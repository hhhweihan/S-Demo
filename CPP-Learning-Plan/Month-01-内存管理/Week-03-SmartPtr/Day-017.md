## 今日目标

昨天的 `shared_ptr` 已经能解决“多人共享同一资源”的问题，但它会带来一个新的坑：

> 如果两个对象都用 `SharedPtr` 指向对方，那么谁都不会先归零，最后对象永远不释放。

这就是循环引用。

`weak_ptr` 的设计目标很明确：

1. **能观察对象是否还活着**
2. **能在需要时临时升级成 `SharedPtr`**
3. **但自己绝不能参与对象所有权**

一句话概括：

> `weak_ptr` 认识对象，但不拥有对象。

---

## 为什么 `shared_ptr` 不够用

看一个最常见的环：

```cpp
struct Node {
  SharedPtr<Node> next;
};
```

如果有：

```cpp
SharedPtr<Node> a(new Node());
SharedPtr<Node> b(new Node());
a->next = b;
b->next = a;
```

那么：

- `a` 的对象被外部 `a` 和 `b->next` 持有
- `b` 的对象被外部 `b` 和 `a->next` 持有

哪怕外部两个变量都离开作用域，环内部仍然彼此持有，`use_count` 不会归零，于是两边都不会析构。

所以我们需要一种“指向控制块但不增加共享拥有者数量”的指针，这就是 `weak_ptr`。

---

## 核心模型

可以把 `shared_ptr` 和 `weak_ptr` 的角色分开记：

- `SharedPtr<T>`：拥有者，增加和减少 `use_count`
- `WeakPtr<T>`：观察者，只增加和减少 `weak_count`

控制块里的两个计数分别代表：

- `use_count`：当前有多少共享拥有者
- `weak_count`：当前有多少弱引用观察者

当 `use_count == 0` 时：

- 对象本身要销毁

当 `use_count == 0 && weak_count == 0` 时：

- 控制块本身才能销毁

这就是为什么昨天要强调“对象生命周期”和“控制块生命周期”是两回事。

---

## `WeakPtr<T>` 最小结构

教学版可以先写成这样：

```cpp
template<typename T>
class WeakPtr {
  T* ptr_ = nullptr;
  ControlBlockBase* control_ = nullptr;
};
```

这里保留 `ptr_` 主要是为了让 `lock()` 返回 `SharedPtr<T>` 时更直接。

注意：`WeakPtr<T>` 自己不能在析构里删对象，它只能改 `weak_count`。

---

## 参考实现

下面这个版本基于 Day 16 的 `SharedPtr` 控制块模型：

```cpp
template<typename T>
class WeakPtr;

template<typename T>
class SharedPtr {
  T* ptr_ = nullptr;
  ControlBlockBase* control_ = nullptr;

  void release_current() {
    if (!control_) {
      return;
    }

    if (--control_->use_count == 0) {
      control_->destroy_object();
      if (control_->weak_count == 0) {
        delete control_;
      }
    }

    ptr_ = nullptr;
    control_ = nullptr;
  }

  SharedPtr(T* p, ControlBlockBase* c, bool add_ref) noexcept
    : ptr_(p), control_(c) {
    if (control_ && add_ref) {
      ++control_->use_count;
    }
  }

public:
  SharedPtr() noexcept = default;

  explicit SharedPtr(T* p) : ptr_(p) {
    if (p) {
      control_ = new ControlBlockPtr<T>(p);
    }
  }

  ~SharedPtr() {
    release_current();
  }

  SharedPtr(const SharedPtr& other) noexcept
    : ptr_(other.ptr_), control_(other.control_) {
    if (control_) {
      ++control_->use_count;
    }
  }

  SharedPtr(SharedPtr&& other) noexcept
    : ptr_(other.ptr_), control_(other.control_) {
    other.ptr_ = nullptr;
    other.control_ = nullptr;
  }

  SharedPtr& operator=(const SharedPtr& other) noexcept {
    if (this != &other) {
      release_current();
      ptr_ = other.ptr_;
      control_ = other.control_;
      if (control_) {
        ++control_->use_count;
      }
    }
    return *this;
  }

  SharedPtr& operator=(SharedPtr&& other) noexcept {
    if (this != &other) {
      release_current();
      ptr_ = other.ptr_;
      control_ = other.control_;
      other.ptr_ = nullptr;
      other.control_ = nullptr;
    }
    return *this;
  }

  T* get() const noexcept { return ptr_; }
  T& operator*() const { return *ptr_; }
  T* operator->() const noexcept { return ptr_; }
  int use_count() const noexcept { return control_ ? control_->use_count.load() : 0; }
  explicit operator bool() const noexcept { return ptr_ != nullptr; }

  friend class WeakPtr<T>;
};

template<typename T>
class WeakPtr {
  T* ptr_ = nullptr;
  ControlBlockBase* control_ = nullptr;

  void release_weak() {
    if (!control_) {
      return;
    }

    if (--control_->weak_count == 0 && control_->use_count == 0) {
      delete control_;
    }

    ptr_ = nullptr;
    control_ = nullptr;
  }

public:
  WeakPtr() noexcept = default;

  WeakPtr(const SharedPtr<T>& shared) noexcept
    : ptr_(shared.ptr_), control_(shared.control_) {
    if (control_) {
      ++control_->weak_count;
    }
  }

  WeakPtr(const WeakPtr& other) noexcept
    : ptr_(other.ptr_), control_(other.control_) {
    if (control_) {
      ++control_->weak_count;
    }
  }

  WeakPtr(WeakPtr&& other) noexcept
    : ptr_(other.ptr_), control_(other.control_) {
    other.ptr_ = nullptr;
    other.control_ = nullptr;
  }

  ~WeakPtr() {
    release_weak();
  }

  WeakPtr& operator=(const WeakPtr& other) noexcept {
    if (this != &other) {
      release_weak();
      ptr_ = other.ptr_;
      control_ = other.control_;
      if (control_) {
        ++control_->weak_count;
      }
    }
    return *this;
  }

  WeakPtr& operator=(const SharedPtr<T>& shared) noexcept {
    release_weak();
    ptr_ = shared.ptr_;
    control_ = shared.control_;
    if (control_) {
      ++control_->weak_count;
    }
    return *this;
  }

  SharedPtr<T> lock() const noexcept {
    if (!control_ || control_->use_count == 0) {
      return SharedPtr<T>();
    }
    return SharedPtr<T>(ptr_, control_, true);
  }

  bool expired() const noexcept {
    return !control_ || control_->use_count == 0;
  }

  int use_count() const noexcept {
    return control_ ? control_->use_count.load() : 0;
  }
};
```

## `lock()` 为什么是关键接口

`weak_ptr` 不能直接解引用，因为它不拥有对象，无法保证对象此刻还活着。

所以标准做法不是：

```cpp
weak->hello();
```

而是：

```cpp
if (auto sp = weak.lock()) {
  sp->hello();
}
```

`lock()` 做了两件事：

1. 检查对象是否还存活，也就是 `use_count > 0`
2. 如果对象还活着，返回一个新的 `SharedPtr<T>`，把这次访问变成一次临时共享拥有

这就是 `weak_ptr` 的本质语义：

> 想访问对象，先申请一次临时所有权；申请不到，就说明对象已经没了。

## 循环引用样例

### 错误版本：双方都用 `SharedPtr`

```cpp
struct Node {
  int value;
  SharedPtr<Node> next;

  explicit Node(int v) : value(v) {}
  ~Node() { std::cout << "Node(" << value << ") dtor\n"; }
};

int main() {
  SharedPtr<Node> a(new Node(1));
  SharedPtr<Node> b(new Node(2));

  a->next = b;
  b->next = a;
}
```

这段代码理论上会导致两个 `Node` 都无法释放。

### 正确版本：回指改用 `WeakPtr`

```cpp
struct Node {
  int value;
  WeakPtr<Node> next;

  explicit Node(int v) : value(v) {}
  ~Node() { std::cout << "Node(" << value << ") dtor\n"; }
};

int main() {
  SharedPtr<Node> a(new Node(1));
  SharedPtr<Node> b(new Node(2));

  a->next = b;
  b->next = a;
}
```

这时只有外部的 `a` 和 `b` 真正拥有对象，离开作用域后 `use_count` 能正常归零，析构就会发生。

## 建议测试点

### 1. `lock()` 成功场景

```cpp
SharedPtr<Test> sp(new Test(10));
WeakPtr<Test> wp = sp;

auto again = wp.lock();
std::cout << again.use_count() << "\n";
```

预期：`again` 非空，且 `use_count` 相比原来增加 1。

### 2. `lock()` 失败场景

```cpp
WeakPtr<Test> wp;
{
  SharedPtr<Test> sp(new Test(20));
  wp = sp;
}

auto again = wp.lock();
std::cout << (again ? "alive" : "expired") << "\n";
```

预期：对象已析构，`again` 为空。

### 3. 循环引用打破

用上面的 `Node` 样例，观察作用域结束后析构日志是否打印。

## 今天最容易犯的错

### 1. `WeakPtr` 构造时误增加 `use_count`

一旦这样写，`weak_ptr` 就偷偷变成拥有者了，循环引用问题不会被解决。

### 2. `lock()` 直接返回 `SharedPtr<T>(ptr_)`

这会新建一个新的控制块，而不是共享已有控制块，语义完全错误。

`lock()` 返回的 `SharedPtr` 必须接到**原来的控制块**上。

### 3. 对象析构后立刻删控制块

如果还有 `weak_ptr` 在观察，控制块还得继续活着，否则 `weak_ptr::expired()` 和 `lock()` 就没有依据了。

### 4. `weak_count` 减到 0 时不判断 `use_count`

只有 `use_count == 0 && weak_count == 0`，控制块才能删。

## 和标准库 `std::weak_ptr` 的差距

今天这个教学版和标准库相比，至少还缺：

1. 更严格的线程安全语义
2. 更完整的构造、转换和 `owner_before` 等接口
3. 与 `enable_shared_from_this` 的自然联动
4. 对 `lock()` 原子升级路径的更严谨实现

但核心模型已经完整了：

> `weak_ptr` 的价值不在于“少一个接口”，而在于它把“观察”和“拥有”彻底分开了。

## 今日总结（完成后填写）

1. `WeakPtr<T>` 不拥有对象，因此它只增加 `weak_count`，不增加 `use_count`。
2. `lock()` 是弱引用转强引用的唯一正确入口，它返回的是共享原控制块的新 `SharedPtr<T>`。
3. 对象销毁和控制块销毁是两阶段模型：对象先死，控制块可能继续活着，直到最后一个弱引用也消失。
4. `WeakPtr` 的最大工程意义，是打破 `SharedPtr` 形成的循环引用。

**明天衔接：** 明天的 `enable_shared_from_this` 本质上就是“对象内部保存一个指向自己控制块的弱引用”。如果今天的 `WeakPtr` 模型清楚了，Day 18 就只是顺理成章的一步。

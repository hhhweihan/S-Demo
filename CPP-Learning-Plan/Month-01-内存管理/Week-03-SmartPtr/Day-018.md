## 今日目标

前两天已经有了：

- `SharedPtr<T>`：拥有控制块
- `WeakPtr<T>`：观察控制块

今天要解决的是一个非常实际的问题：

> 如果对象内部想把“自己”作为 `SharedPtr` 传出去，应该怎么拿到那个共享控制块？

很多人第一反应会写：

```cpp
SharedPtr<T>(this)
```

这通常是错的，因为它会给同一个裸指针再新建一个控制块，最后形成两个彼此不知道对方存在的 `shared_ptr` 体系，最终双重释放。

`enable_shared_from_this` 的核心作用，就是让对象内部能够安全地回到“自己原来那套控制块”。

---

## 为什么 `SharedPtr<T>(this)` 是危险的

假设：

```cpp
struct Widget {
    SharedPtr<Widget> self() {
        return SharedPtr<Widget>(this);
    }
};
```

如果外部已经有：

```cpp
SharedPtr<Widget> p(new Widget());
auto p2 = p->self();
```

那么：

- `p` 有一套控制块 A
- `p2` 又基于 `this` 新建了一套控制块 B

控制块 A 和 B 都觉得自己是唯一合法的回收者。最后对象会被删两次。

所以正确做法不是“再造一个 `SharedPtr`”，而是“回到原来的控制块”。

---

## 设计思路

对象内部想拿回自己的 `SharedPtr`，最自然的方法是：

1. 在对象里存一份指向原控制块的 `WeakPtr<T>`
2. 需要时调用 `weak_this_.lock()`
3. 拿到一个和外部共享同一控制块的新 `SharedPtr<T>`

这就是 `EnableSharedFromThis<T>` 的本质。

---

## 基类设计

教学版可以先这样写：

```cpp
template<typename T>
class EnableSharedFromThis {
protected:
    mutable WeakPtr<T> weak_this_;

public:
    SharedPtr<T> shared_from_this() {
        return weak_this_.lock();
    }

    SharedPtr<const T> shared_from_this() const {
        return weak_this_.lock();
    }

    template<typename U>
    friend class SharedPtr;
};
```

这里把 `SharedPtr` 声明为友元，是为了让 `SharedPtr` 在创建对象后有机会初始化 `weak_this_`。

---

## `SharedPtr` 里要补的逻辑

关键不是在每次拷贝时都初始化，而是：

> 在“首次把裸指针接入一套控制块”时，如果对象继承自 `EnableSharedFromThis<T>`，就把它内部的 `weak_this_` 指到这套控制块上。

可以加一个私有辅助函数：

```cpp
template<typename U>
void enable_weak_this(U* p) noexcept {
    if constexpr (std::is_base_of_v<EnableSharedFromThis<U>, U>) {
        p->weak_this_ = *this;
    }
}
```

然后在 `SharedPtr(T* p)` 构造成功后调用。

---

## 参考实现

下面是教学版最小链路：

```cpp
#include <type_traits>

template<typename T>
class EnableSharedFromThis {
protected:
    mutable WeakPtr<T> weak_this_;

public:
    SharedPtr<T> shared_from_this() {
        return weak_this_.lock();
    }

    SharedPtr<const T> shared_from_this() const {
        return weak_this_.lock();
    }

    template<typename U>
    friend class SharedPtr;
};

template<typename T>
class SharedPtr {
    T* ptr_ = nullptr;
    ControlBlockBase* control_ = nullptr;

    template<typename U>
    void enable_weak_this(U* p) noexcept {
        if constexpr (std::is_base_of_v<EnableSharedFromThis<U>, U>) {
            if (p) {
                p->weak_this_ = *this;
            }
        }
    }

public:
    explicit SharedPtr(T* p) : ptr_(p) {
        if (p) {
            control_ = new ControlBlockPtr<T>(p);
            enable_weak_this(p);
        }
    }

    // 其余拷贝/移动/析构逻辑同前两天
};
```

为什么 `weak_this_ = *this` 是合理的？因为 `WeakPtr` 从 `SharedPtr` 构造时：

- 会共享同一控制块
- 只增加 `weak_count`
- 不增加 `use_count`

这正是我们想要的效果。

## 测试样例

```cpp
#include <iostream>

struct Widget : EnableSharedFromThis<Widget> {
    int value = 42;

    SharedPtr<Widget> self() {
        return shared_from_this();
    }

    void hello() {
        std::cout << "value = " << value << "\n";
    }
};

int main() {
    SharedPtr<Widget> p(new Widget());
    std::cout << "count before = " << p.use_count() << "\n";

    SharedPtr<Widget> p2 = p->self();
    std::cout << "count after = " << p.use_count() << "\n";

    p2->hello();
}
```

### 预期现象

1. `p` 创建后，`use_count == 1`
2. 调用 `p->self()` 后得到 `p2`
3. `p2` 和 `p` 共享同一控制块，所以 `use_count == 2`
4. 两者析构后，对象只销毁一次

---

## 今天最关键的理解

### 1. `shared_from_this()` 不是“重新包装 this”

它是“通过对象内部保存的弱引用，回到原控制块，再拿到一个新的共享句柄”。

### 2. 初始化 `weak_this_` 的时机只有一次

必须在第一套控制块建立后初始化。太早时控制块还不存在，太晚则对象内部已经可能调用 `shared_from_this()`。

### 3. `enable_shared_from_this` 依赖 `weak_ptr`

如果没有昨天的 `WeakPtr`，今天这套机制就无从成立。

---

## 今天最容易犯的错

### 1. 在 `shared_from_this()` 里直接返回 `SharedPtr<T>(this)`

这是最危险的错误，会制造第二套控制块。

### 2. 每次拷贝 `SharedPtr` 都重写 `weak_this_`

通常没必要。真正重要的是第一套控制块建立时把对象内部弱引用接上。

### 3. 对象不是由 `SharedPtr` 创建却调用 `shared_from_this()`

例如：

```cpp
Widget w;
auto p = w.shared_from_this();
```

这时 `weak_this_` 其实没有绑定到任何控制块，行为应视为非法或返回空。标准库里这里通常会抛 `bad_weak_ptr`。

---

## 和标准库的差距

今天的教学版与标准库相比还差：

1. `bad_weak_ptr` 异常语义
2. 更完善的类型兼容与继承层次处理
3. 对 aliasing constructor、数组等场景的完整覆盖
4. 更严谨的 const / non-const 重载和模板约束

但只要核心链路清楚，这个知识点已经学到了本质：

> `enable_shared_from_this` 就是把“对象内部拿回共享所有权”这件事，建立在同一控制块之上。

---

## 今日总结（完成后填写）

1. 对象内部绝不能通过 `SharedPtr<T>(this)` 自己再造一套控制块。
2. `EnableSharedFromThis<T>` 内部保存的是 `WeakPtr<T> weak_this_`，需要时通过 `lock()` 变成 `SharedPtr<T>`。
3. `weak_this_` 的初始化必须发生在 `SharedPtr` 首次接管对象、控制块刚建立完成时。
4. `shared_from_this()` 真正返回的是“共享原控制块的新句柄”，而不是“重新包装 this 的新智能指针”。

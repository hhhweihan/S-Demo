## 今日目标

`unique_ptr` 是最容易上手、也最能帮助理解 RAII 的智能指针。

今天不追求对标标准库的全部细节，只抓住三件事：

1. **对象生命周期要和栈对象绑定。** `UniquePtr<T>` 析构时自动 `delete ptr_`。
2. **所有权只能移动，不能拷贝。** 否则会出现双重释放。
3. **“放手”和“接手”要写清楚。** `release()` 是放手，`reset()` 是接手并清理旧资源。

如果这三个点完全吃透，后面的 `shared_ptr` 和 `weak_ptr` 才不会只是“背接口”。

---

## 核心设计

最小版本只需要一个成员：

```cpp
T* ptr_ = nullptr;
```

它表示“当前 `UniquePtr` 独占管理的那块资源”。围绕这个指针，接口可以分成四类：

### 1. 生命周期

- 构造：接收裸指针，建立所有权
- 析构：如果 `ptr_ != nullptr`，执行 `delete ptr_`

### 2. 所有权转移

- 移动构造：偷走对方的指针，并把对方置空
- 移动赋值：先释放自己的旧资源，再接管对方的资源，并把对方置空

### 3. 访问资源

- `get()`：仅观察，不转移所有权
- `operator*()` / `operator->()`：像普通指针一样使用对象
- `operator bool()`：判断当前是否持有资源

### 4. 主动管理

- `release()`：交出所有权，但不删除对象
- `reset(p)`：先删旧对象，再接管新对象 `p`

## 为什么必须禁止拷贝

假设允许下面这段代码成立：

```cpp
UniquePtr<int> a(new int(42));
UniquePtr<int> b = a;
```

那么 `a.ptr_` 和 `b.ptr_` 会指向同一块内存。两个对象离开作用域时都会执行 `delete`，结果就是 **double free**。

所以对 `unique_ptr` 来说，正确做法不是“运行时小心一点”，而是直接把错误扼杀在编译期：

```cpp
UniquePtr(const UniquePtr&) = delete;
UniquePtr& operator=(const UniquePtr&) = delete;
```

这也是 C++ 资源管理里非常重要的一条原则：

> 能在类型系统里表达的约束，就不要留到运行时碰运气。

## 参考实现

下面这个版本已经覆盖今天需要理解的核心语义：

```cpp
template<typename T>
class UniquePtr {
  T* ptr_ = nullptr;

public:
  explicit UniquePtr(T* p = nullptr) noexcept : ptr_(p) {}

  ~UniquePtr() {
    delete ptr_;
  }

  UniquePtr(UniquePtr&& other) noexcept : ptr_(other.ptr_) {
    other.ptr_ = nullptr;
  }

  UniquePtr& operator=(UniquePtr&& other) noexcept {
    if (this != &other) {
      delete ptr_;
      ptr_ = other.ptr_;
      other.ptr_ = nullptr;
    }
    return *this;
  }

  UniquePtr(const UniquePtr&) = delete;
  UniquePtr& operator=(const UniquePtr&) = delete;

  T* get() const noexcept {
    return ptr_;
  }

  T& operator*() const {
    return *ptr_;
  }

  T* operator->() const noexcept {
    return ptr_;
  }

  T* release() noexcept {
    T* raw = ptr_;
    ptr_ = nullptr;
    return raw;
  }

  void reset(T* p = nullptr) noexcept {
    if (ptr_ != p) {
      delete ptr_;
      ptr_ = p;
    }
  }

  explicit operator bool() const noexcept {
    return ptr_ != nullptr;
  }
};
```

## 每个接口背后的语义

### 1. 析构函数

```cpp
~UniquePtr() {
  delete ptr_;
}
```

这里体现的是 RAII 的核心：**资源跟着对象生命周期自动回收**。

注意：`delete nullptr` 是安全的，所以这里不需要先写 `if (ptr_)`。

### 2. 移动构造

```cpp
UniquePtr(UniquePtr&& other) noexcept : ptr_(other.ptr_) {
  other.ptr_ = nullptr;
}
```

这一步不是“复制一份资源”，而是“把资源所有权从 `other` 身上扒下来”。

`other` 被置空后，析构时就不会重复释放同一块内存。

### 3. 移动赋值

```cpp
UniquePtr& operator=(UniquePtr&& other) noexcept {
  if (this != &other) {
    delete ptr_;
    ptr_ = other.ptr_;
    other.ptr_ = nullptr;
  }
  return *this;
}
```

顺序非常关键：

1. 先释放自己当前持有的旧资源
2. 再接管 `other` 的资源
3. 最后把 `other` 置空

如果忘了第一步，就会泄漏旧资源；如果忘了第三步，就会双重释放。

### 4. release()

```cpp
T* release() noexcept {
  T* raw = ptr_;
  ptr_ = nullptr;
  return raw;
}
```

`release()` 的意思不是“删除资源”，而是：

> 这块资源我不管了，你拿裸指针自己负责。

所以调用 `release()` 后，必须有人接手那根裸指针，否则就会泄漏。

### 5. reset()

```cpp
void reset(T* p = nullptr) noexcept {
  if (ptr_ != p) {
    delete ptr_;
    ptr_ = p;
  }
}
```

`reset()` 代表“换一块资源继续独占管理”。

`if (ptr_ != p)` 这一层判断是为了避免把同一根指针传回来时发生自删问题。

## 建议测试代码

可以用一个带打印的类来观察生命周期：

```cpp
#include <iostream>
#include <utility>

struct Test {
  int value;

  explicit Test(int v) : value(v) {
    std::cout << "Test(" << value << ") ctor\n";
  }

  ~Test() {
    std::cout << "Test(" << value << ") dtor\n";
  }

  void hello() const {
    std::cout << "hello: " << value << "\n";
  }
};

int main() {
  {
    UniquePtr<Test> p(new Test(10));
    p->hello();
  }

  std::cout << "---- move ----\n";

  {
    UniquePtr<Test> a(new Test(20));
    UniquePtr<Test> b(std::move(a));

    std::cout << "a is " << (a ? "not null" : "null") << "\n";
    std::cout << "b is " << (b ? "not null" : "null") << "\n";
  }

  std::cout << "---- release/reset ----\n";

  {
    UniquePtr<Test> p(new Test(30));
    Test* raw = p.release();
    std::cout << "after release, p is " << (p ? "not null" : "null") << "\n";
    delete raw;

    p.reset(new Test(40));
  }

  return 0;
}
```

### 预期现象

1. 第一段作用域结束时，会自动打印析构日志
2. `std::move(a)` 之后，`a` 应该变成空指针，`b` 持有资源
3. `release()` 后，`p` 为空，但对象不会自动析构，必须手动 `delete raw`
4. `reset(new Test(40))` 后，新对象会由 `p` 接管，并在离开作用域时自动释放

## 禁止拷贝的验证方式

下面这段代码应该无法通过编译：

```cpp
UniquePtr<Test> a(new Test(1));
UniquePtr<Test> b = a;
```

如果编译器报错，说明行为是正确的。这里的“报错”不是坏事，而是类型系统在保护资源所有权模型。

---

## 今天最容易犯的错

### 1. 移动后忘记把源对象置空

这会直接导致双重释放，是 `unique_ptr` 初学实现里最常见的 bug。

### 2. `release()` 之后误以为还会自动析构

不会。`release()` 的语义就是“我不管了”。调用后如果没有新的接管者，就会泄漏。

### 3. 在移动赋值里没有先释放旧资源

例如：

```cpp
ptr_ = other.ptr_;
other.ptr_ = nullptr;
```

如果直接这样写，当前对象原来持有的资源就丢了，形成内存泄漏。

### 4. 把 `get()` 当成转移所有权

`get()` 只是拿到底层裸指针做观察或临时调用，不会修改所有权；真正交出所有权的是 `release()`。

## 和标准库 `std::unique_ptr` 的差距

今天实现的是教学版，和标准库相比，至少还缺这些点：

1. **自定义删除器。** 标准库可以管理 `FILE*`、socket、数组等非 `delete` 资源。
2. **数组特化。** `unique_ptr<T[]>` 需要配合 `delete[]`。
3. **更完整的构造与赋值约束。** 标准库对模板转换、删除器类型和异常安全都更严谨。
4. **`make_unique`。** 可以避免显式 `new`，接口更安全也更现代。

但对今天来说，这些都不是重点。重点仍然只有一句话：

> `unique_ptr` 的本质不是“会自动 delete 的指针”，而是“独占所有权的对象”。

## 今日总结（完成后填写）

1. `UniquePtr<T>` 的核心只有一个成员 `T* ptr_`，但真正重要的是它表达的**所有权规则**。
2. 析构函数体现 RAII；移动构造和移动赋值体现“所有权可转移但不可复制”。
3. `get()`、`release()`、`reset()` 这三个接口名字很像，但语义完全不同：
   - `get()` 只观察
   - `release()` 交出管理权，不析构对象
   - `reset()` 先释放旧资源，再接管新资源

## 编号 337 — Storage 抽象与持久化边界：crash 丢全部易失态，restart 从磁盘真重载

**掌握标准：能不看代码说清「Raft 哪些状态必须持久、哪些是易失的」，并解释为什么 restart() 必须
从 Storage::load() 完全重建、而不能靠对象里残留的字段「魔法保留」。**

### 持久 vs 易失的红线

Raft 把节点状态切成两半，这条线是崩溃恢复正确性的根：

| 类别 | 字段 | 掉电后 |
| --- | --- | --- |
| **持久（必须落盘）** | `currentTerm` / `votedFor` / `log` / `snapshot`(+`lastIncludedIndex/Term`) | 必须原样幸存 |
| **易失（重启重建）** | `role` / `commitIndex` / `lastApplied` / 状态机 / `nextIndex[]` / `matchIndex[]` | 全部丢弃，从零重建 |

- `currentTerm`/`votedFor` 必须持久，否则一个节点崩溃重启后可能在**同一任期投第二票**，破坏「每任期至多一个 Leader」。
- `log` 必须持久，否则已复制给多数派的条目在 Leader 重启后凭空消失，违反「已提交不丢失」。
- `commitIndex`/`lastApplied` **故意不持久**：重启后从 0 重建，靠重放 log（+snapshot）把状态机推回去；持久化它们只会带来「记录的 commit 超过实际落盘 log」的不一致风险。

### 为什么要 Storage 抽象

改造前的仿真 `restart()` 直接复用活对象里的字段，崩溃「从没真正测过持久性」——忘了持久化某个字段也照样能恢复，因为它压根没丢。引入 `Storage` 就是把这条边界变成**代码强制**的：

```cpp
class Storage {
    virtual void saveHardState(int currentTerm, int votedFor) = 0;   // term+vote，小而频繁
    virtual void saveLog(const std::vector<LogEntry>& log) = 0;      // 截断/追加都全量重写
    virtual void saveSnapshot(int lii, int lit,
                              const std::string& snap,
                              const std::vector<LogEntry>& log) = 0;
    virtual PersistentState load() = 0;   // 崩溃后唯一的真相来源
};
```

- **每一次** `currentTerm/votedFor/log` 变更都走 `Storage`；
- `crash()` 直接 `node = Node(id, storage)`，**丢掉全部易失态**（连同活对象里的持久字段副本）；
- `restart()` 也 `node = Node(id, storage)`，然后 `loadFromStorage()` 从 `Storage::load()` 把持久态读回来，重放重建状态机。

于是「忘了持久化」= 那个字段在 restart 后真的是默认值，测试立刻抓到。

### 两个实现：MemStorage / FileStorage

- **MemStorage（默认）**：blob 存在内存里。`crash()/restart()` 只丢活 Node，这个 blob 活着——这正是「稳定存储」给的保证，且零 IO、保仿真确定性与速度。5 个既有 chaos 测试全部继续走它。
- **FileStorage**：真 `open/write/fsync`，见 [[338|编号 338]] 里复用的原子写协议。它让 `restart()` 变成**真磁盘重载**，用于崩溃持久性测试。

### 原子写 + CRC（复用 F3 的崩溃安全协议）

`FileStorage::flush()` 把整个持久镜像一次性原子落盘：

```
写 tmp → fsync(tmp) → rename(tmp → path)  → fsync(dir)
```

`rename(2)` 原子，崩溃只会留下「完整旧文件」或「完整新文件」，绝不出现撕裂的半文件；CRC32 前缀再兜住「第一次落盘时 tmp 只写了一半」这种没有旧文件可回退的情况。`load()` 在文件缺失 / CRC 校验失败时返回默认（全新）状态——等价于「还没有任何东西落盘」。macOS 无 `fdatasync`，用 `fsync`（真盘持久要 `F_FULLFSYNC`，与 [[197|编号 197]] 同一课）。

### 验证

- `FileStorageSurvivesFullClusterReboot`：整集群写入若干条后全部 `crash`，再全部 `restart`（走 FileStorage），断言 term/votedFor/log 完整重载、已提交前缀不丢。
- `ReelectsAfterLeaderCrashesWithFileStorage`（seed 1–8）：Leader 在真磁盘存储下崩溃，剩余多数派重新选主，重启后无任何安全不变量违反。
